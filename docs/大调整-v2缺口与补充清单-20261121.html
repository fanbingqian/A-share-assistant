二、需要补充 / 缺失的内容

A. 需你本人操作（我无法代做）

项为什么怎么做
正式安装官方 Hermes Agent 本机 wsl.exe 被安全策略拦截，我无法从这里安装/启动 WSL2；官方 Hermes 原生 Windows 仅实验性支持。 在 WSL2(Ubuntu) 里执行 hermes-bridge/setup-wsl2.sh，或在 PowerShell 用官方 iex (irm https://hermes-agent.nousresearch.com/install.ps1)。装好后把 DeepSeek Key 配进去，桥接服务默认监听 127.0.0.1:8765，状态栏会显示 Hermes。
DeepSeek 费用与额度 对话/预测/整理都按 token 计费；现有软上限 20万 token/日。 在设置或 data/config.json 的 agent.maxTokensPerDay 调整。

B. 数据源缺口（决定「实时/全量」程度）

缺口影响建议
确定性财经事件的权威日历
（美联储/各国指标/展会/全球会议的具体日期）		当前事件日期按制度性规律推算（B级「待核实」），非实时抓取；展会、全球重大会议覆盖不全。接入经济日历数据源（如 Investing.com / Trading Economics / 各国央行官网 RSS），把 B 级升级为 A 级已确认日期；展会与会议用行业日历源补充。
板块真实主力资金净流入当前「资金持续流入」用多周期相对强度近似，不是真实净流入金额。接入东财/同花顺行业资金流接口（按细分行业 dml 净额），把持续性判断从「超额同向」升级为「连续N日净流入」。
防守型个股与 ETF 池第三类选股当前只给防御类板块线索，个股/ETF 清单为空（不编造标的）。接入股息率、波动率、最大回撤数据与 ETF 全量列表，按「低波+高股息+弱市抗跌」自动筛选；或手工维护一份清单文件。
全市场日线快照「承压不跌」与观察池基于候选池（约18只），非全市场扫描。用同花顺 Financial-API 的 Market Dumps 每天落一份全市场日线，即可对全市场跑 MA5/防守型筛选（此前调研已确认这是最优路径）。
海外指标稳定性实测海外源(LetsVPN 环境)频繁 socket hang up，已自动降级缓存。保持程序级故障转移；如需稳定实时，为海外源单独配代理或换源。

C. 设计/机制缺口（影响可信度与闭环）

  • 预测的可证伪留痕：Hermes 生成的方向依据目前是即时文本，尚未写入「预测账本」做事后命中检验。建议落 predictions.jsonl，次日复盘核对，纳入经验库。
  • 事件→板块→个股的因果链：目前给出「相关板块」，但事件到具体受益个股的映射仍需人工确认；建议接映射表并标注证据等级。
  • 知识图谱的语义质量：无 LLM 时用关键词规则兜底，节点较粗；接上 Hermes 后自动抽取三元组质量更高。冲突边(contradicts)不自动消解，需人工审核——这是刻意设计，不是缺陷。
  • 弹框提醒的到达率：当前用页面内 toast + 告警流；桌面系统通知需浏览器授予 Notification 权限，且页面需保持打开。若要「关页面也提醒」，需接消息网关（Hermes 支持 Telegram/企业微信等 20+ 平台）。
  • 权限与安全：Hermes 桥接默认只监听 127.0.0.1；生产使用建议给桥接加 token 校验，并限制 Hermes 的工具集（hermes tools）为只读，避免智能体误操作文件。

三、怎么切换成 Hermes 正式核心

1）WSL2 跑通 hermes chat -q "你好"；
2）启动桥接 python3 hermes_bridge.py --port 8765；
3）Windows 侧确认 http://127.0.0.1:8765/health 能通（WSL2 与 Windows 网络互通需按脚本提示设置 IP 或端口转发）；
4）在 data/config.json 把 agent.hermes.backend 设为 official（当前 auto 会自动探测）；
5）重启程序，左侧状态栏显示「Hermes」即切换成功；失败仍自动回 DeepSeek，不会中断服务。
