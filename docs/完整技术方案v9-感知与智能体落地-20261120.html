0｜一句话结论

智能体的「感知」不是天生的，是三件确定性组件拼出来的：观察者（定时轮询数据源）→ 变化检测（diff）→ 触发（只把增量喂给大模型解读）。你的系统已有 13 个定时器，感知地基已存在；本轮只需新增「公告观察者 + 新闻观察者」两个模块，大脑接 DeepSeek，数据层直接复用开源技能 a-stock-data（Apache-2.0，公告/新闻/龙虎榜/题材归因全覆盖）。事件解读后按已有设计分四路：Flag 提示 / 假说卡 / 事实账本 / 仅通知。对话内容与每日复盘结果均可入库，但走两条闸门不同的链路——经验链路快而不改分，因子链路慢而能改分。

1｜概念校准：智能体怎么「感知」到一个突发利好

大模型确实没有感知能力，但智能体也不会自动拥有——所谓 Agent 感知，在所有成熟系统里都是同一个模式（GitHub 上的 Pi Durable News Agent、daily_stock_analysis、PanWatch 全是这么做的）：

三要素做什么在本项目的实现
① 观察者定时轮询/接收推送：公告源（巨潮/东财）、新闻源（东财/财联社/华尔街见闻）、股池价格异动新增 watchers.js（公告观察者、新闻观察者）；股池价格异动已在现有定时器里
② 变化检测与上次快照 diff，只留增量；带冷却时间、日触发上限（借鉴 PanWatch 的较真设计）新增快照缓存 data/watch-last.json；diff 纯代码实现，LLM 不参与
③ 触发增量 ≥ 阈值才唤醒 LLM 解读；无增量不花钱、不产生幻觉机会DeepSeek 调用发生在 diff 命中之后；每日解读预算封顶

为什么这个顺序重要：如果让大模型「自己去看」全量数据再判断有没有新闻，每次轮询都在烧 token、每次都在制造幻觉机会；让代码先 diff、模型只看增量，成本降一个量级，幻觉面也缩到最小。这正是 Pi Durable News Agent 的「cron 扫源 → 相关性门槛 → 同故事去重 → 重要性排序」模式，可直接借鉴其门槛判定思路。

5｜两条入库链路（对话内容、复盘结果都能进库，但闸门不同）

链路一：经验入库 —— 快，但永不改分

对话内容、复盘分析结果、粘贴的外部稿件，经 R1 抽取「主张/证据/来源/时点」四元组后进待审区 → 数据回填 + 反例计数 → 人工采纳后只变成 Flag 提示、假说卡、L3 叙事案例（affectsScore=false）。对话原文永久保留于 conversations.jsonl 可删除；对话里出现的数字/日期一律置 null。

复盘结果比对话天然可信一层——因为它的入口是确定性统计（7 类缓存），不是模型猜的。但要让复盘分析结果升级为「经验」，仍需 precommit：结果出来前先登记预判与证伪条件，事后对照才有采纳资格。

链路二：因子入库 —— 慢，但能改分

任何来源的因子候选（对话分诊出的、复盘总结出的、素材卡里的）统一进 navplan 状态机：draft → 字段白名单校验 → 影子运行（只算不进分）→ Rank IC 复检（复用 ic.js）→ n≥30 / IC>0.03 / IR>0.5 / 样本外不劣化 → 人工最后否决 → 有界上架（±2 分、乘数 0.8–1.25、不翻符号）。统计闸门是代码，模型替代不了；默认鼓励变成 Flag 而不是新因子。

7｜安全与合规边界

  • 不自动下单：全套系统不产生委托指令，不落入程序化交易报备框架；券商 MCP 只读、禁挂交易类工具。
  • 可整体关闭：智能体开关在 v8 顶栏；watchers 与 DeepSeek 调用全停时，8777 主服务选股监控照常。
  • 隐私：发给 DeepSeek 的只有脱敏事实（代码、价格、公告标题），无账户/持仓金额/身份信息。
  • 数据自用：行情/公告数据个人自用、注明来源、不对外分发。
  • 技能安全：只装纯 Markdown 技能（公开技能约 26.1% 含漏洞、带脚本的风险高 2.12 倍），装前通读。
