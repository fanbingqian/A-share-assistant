个人经验工程与因素体系设计

项目：GlobalMarketMonitor（D:\WorkBuddy\projects\GlobalMarketMonitor）｜文档版本：2026-11-19 v1｜性质：架构设计，不含任何实时行情数据或个股建议｜核验时点：2026-11-19 18:4x（北京时间，盘后）

结论先行

1 · 因素体系「全面」的正确含义

你已在《选股方法论规格与程序覆盖矩阵》里写下 31 条规格。它们应重组为宏观 / 中观 / 微观三层 × Gate / Score / Explain 三类用途，只有 Score 列允许改分。按因子研究纪律，5–10 个能验证的强因子优于 30 个弱因子；把 31 条全塞进评分公式会在小样本上稳定过拟合。

2 · 专业知识不放模型里，放知识卡里

「有专业知识的智能体」应实现为可溯源的知识卡 + 受限三动作（归类口语复盘、生成待验证假说、把确定性结果翻译成人话），而不是让模型自由推理后给结论。模型参数里的记忆不可审计、不可证伪。

3 · 经验必须分级，且必须事前登记

「利好出货 / 提前布局」事后怎么解释都自圆其说。系统必须记录 precommit：事前预判 + 证伪条件，事后只做对照。没有事前登记的复盘，写进知识库的只是故事，不是经验。

4 · 自我调整 = 影子验证 + 人工闸门

经验反哺选股要走五级晋升阶梯：事实 → 假说 → 影子验证（不改分）→ 人工采纳 → 失效检测。冻结基线 v0 永久对照，采纳后仅 ±2 分 / 乘数 0.8–1.25 / 不翻符号，可一键回滚。

本次核验发现一个必须先修的工程问题：现有 4 条「待审经验」是在同一批复盘样本上按 7 个维度切出来的，且命中率与超额收益的统计口径不一致。在这两点修正前，不建议采纳任何一条经验回流评分。详见第二节。

二、三个必须先修的隐患（真实代码核验）

这一节是本次设计里最要紧的部分。你想要的「经验归纳与自我调整」能否可信，取决于这三点，而不是取决于接了多强的模型。

隐患 1 · 同一批样本切七刀：多重比较偏误

server/journal.js:512–559 定义了 LESSON_DIMENSIONS 共 7 个分组维度（信号等级、市值层、板型、情绪阶段、追高风险、连板高度、叠加形态）。buildLessons() 对每个维度逐组统计，只要 n ≥ MIN_N 就生成一条待审经验，既没有多重检验校正，也没有留出样本外（holdout）做复现。

当前 data/journal/lessons.jsonl 里的 4 条全部来自同一批复盘样本的不同切法：

board::turnover1464.3%1.96%低pending
stage::冰点1662.5%1.96%低pending
chase::低(<40)1764.7%2.73%低pending
boards::1板1464.3%1.96%低pending
来源：D:\WorkBuddy\projects\GlobalMarketMonitor\data\journal\lessons.jsonl，读取时点 2026-11-19 18:4x。这些是项目本地历史统计值，仅用于说明工程口径问题，不是行情数据、不是投资结论。

三条经验的 avgExcess 完全相同（1.96%），且组间高度重叠——它们不是三条独立证据，而是同一小批样本被反复切分后的不同投影。18 条样本切 7 个维度，几乎必然能找到若干「60%+ 命中率」的组。把这样的结论回流到评分，等于把噪声固化成规则。

隐患 2 · 命中率与超额收益的口径不一致

journal.js:462 的命中定义是：

hit: bRet == null ? ret > 0 : ret > bRet

而 journal.js:460–461 的注释写的是「不把大盘整体上涨带来的浮盈算成能力」。当基准取不到（benchRet() 返回 null）时，命中判定实际退化成绝对涨跌 ret > 0，与注释相反。data/journal/outcomes.jsonl 首条即 bench: null, excess: null，说明该分支真实发生。

更隐蔽的是 statsOf()（journal.js:481–497）：hitRate 在全部 rows 上算，avgExcess 只在 excess 为有限值的子样本上算。于是同一条经验里的「命中率 64.3%」和「平均超额 1.96%」可能来自两个不同样本集，propose() 却直接拿后者推导乘数。

隐患 3 · 「置信度」只是样本量标签，乘数是样本内拟合

journal.js:586：conf = n ≥ 40 ? '高' : n ≥ 20 ? '中' : '低'——只看样本量，不看效应稳定性、组间差异、时间外表现。propose() 用同一批样本的 avgExcess 直接算乘数（×1.1 / ×1.14），没有样本外验证；applyRules() 一旦人工采纳即乘到评分上（已做 0.8–1.25 的界，这是对的，但只解决了幅度，没解决可信度）。

好消息：rules.json 目前 count=0，一条都没生效。也就是说，现在正是把「影子验证 + 样本外门槛」加进来的最佳时机——不需要回滚任何已生效规则。

建议的 Step 0（今天就能做，零代码）

  1. 把这 4 条 pending 经验标记为「需复核 / 暂不采纳」，而不是 approve；理由是口径与多重比较，不是否定其观察价值。
  2. 先修口径：基准缺失时 hit 应记为 null 并从命中率分母中剔除；统一 hitRate 与 avgExcess 使用同一子集，并在 evidence 里显式写出 nTotal / nWithBench。
  3. 用一张 Markdown 表手工写下 3–5 条 precommit（预判 + 证伪条件 + 观察窗口），让「事前登记」这件事先有实体，再谈自动化。

三、因素体系：三层 × 三类用途

把 31 条规格按「决定什么」分三层，再按「能不能改分」分三类。这是从清单走向可计算系统的关键一步。

层级Gate · 硬性剔除Score · 参与排序Explain · 只做解释
宏观
要不要做、做多大		避险 L1–L4 触发；休市 / 重大数据公布窗口；数据源缺失时禁止出结论两市量能 20 日均量 z-score、量价配合、上涨家数占比、市值风格顺风政策语义解读、外围股指 / 美债期限利差联动、机构言论背景（均标注「需核实原文」）
中观

三类用途的硬规则

  • Gate 布尔判断，只剔除不排序。每个 Gate 必须可逐条复算，带日期、数据源、计算口径；不得由 LLM 判定。
  • Score 唯一允许影响评分的列。新增因子必须先在影子模式跑够样本并过 IC / IR 门槛，才允许进入；已有三组基础分保持冻结基线 v0。
  • Explain 只写进复盘、界面注释、知识卡，永不进入评分公式。「利好出货」这类判断放在这里，既保留你想沉淀的经验，又杜绝叙事影响下单依据。
对小白用户最重要的设计取舍：系统的价值不是给一个更流畅的结论，而是把「哪些是可验证的事实、哪些是待验证的假说、哪些只是故事」显示在界面上，并同时显示样本数与置信度。看起来很专业但无法证伪的解释，会让人更自信地下注——这比不懂更危险。

四、经验四层账本与数据契约

你说的「经验」其实是四种可信度完全不同的东西，混在一个 lessons.jsonl 里必然出问题。建议拆成四层，各自有独立的写入规则。

层内容写入条件能否影响评分
L0 事实账本
Fact		可复算的行情、事件、评分快照、实际操作；每条带 source + 时点 + 口径程序自动写，禁止人工改、禁止 LLM 生成数字不直接改分，是唯一事实源
L1 规则性经验
Rule		确定性、可证伪的判断：「连续两日收盘低于 MA5」「公告前涨幅已透支 → 兑现风险标记」纯代码复算 + 人工确认适用条件与失效条件可作为 Gate 或 Explain；要进 Score 仍需过阶梯
L2 统计性假说
Hypothesis		「某分组在 T+1 有稳定超额」这类需样本裁决的结论（现有 lessons 属于此层）必须事前登记主假说、样本外验证、多重比较校正只有过完第 4 步才允许有界回流
L3 叙事案例库
Case		「利好出货」「提前布局」的个案复盘、外部影响、操作手段的归纳人写入或 LLM 归类，必须带反例与失效条件永不。仅供检索、对照、教学

复盘条目要补的字段

现有 outcomes.jsonl 记的是技术参数（板型、连板高度、情绪阶段、追高风险），没有事件字段，也没有「当时我怎么想」。建议在复盘回贴时补齐四组：

  • 事件上下文：eventType / eventLabel / eventPolarity / eventTime / sourceUrl（把 events-cache.json 与 stock-news-cache.json 的既有字段回贴，不新抓数据）
  • 事前预判：precommitId / expectationGap / expectedHorizon（关联上面的假说）
  • 事后对照：verdict = confirmed | falsified | inconclusive，且理由必须是可复算的价格 / 基准条件
  • 自我观察：actionTaken / planDeviation / emotionTag（用户手填，供第七节的行为账本用）

五、经验晋升阶梯与硬门槛

STEP 1
事实 + 事前登记
写下预判与证伪条件，带日期、来源、时点。无登记者事后不得算经验。
STEP 2
单一主假说
一条假说对应一个可复算触发条件；禁止一次切 7 维挑最好看的组。
STEP 3
影子验证
完全不改分，只记录「若采纳，排序会怎么变」，并与冻结基线 v0 对照。
STEP 4
人工采纳 → 有界回流
过门槛后由人点确认；±2 分、乘数 0.8–1.25、不翻符号、带证据链。
STEP 5
失效检测 → 退役
IC 衰减或市场状态切换自动降权，退役后回到事实层重新积累。
门槛建议值依据与说明
最小样本每组 n ≥ 30，且至少覆盖 3–5 年含完整市场周期的回测窗口（若用历史行情）因子研究方法论：每截面至少 5 个有效标的，回测覆盖 3–5 年；当前 lessons 的 n=14–17 明显不足
因子有效性IC > 0.03 且 IR > 0.5，IC 正比例 > 55%；IC > 0.1 时先查前向偏差因子研究方法论阈值；项目已有 ic.js Rank IC 自检可复用
样本外严格 walk-forward；样本外不得劣于冻结基线；留出 holdout 复现回测拟合度 > 95% 需警惕过拟合；历史回测收益实盘常打 5–7 折
多重比较一次只登记一个主假说；探索性切分的结果只能标「待复现」，不得直接生成 proposal本次核验的隐患 1；探索与验证必须分开
口径统一基准缺失则该样本不进命中率分母；nTotal / nWithBench 显式记录本次核验的隐患 2
回流幅度单次 ±2 分；乘数 0.8–1.25；不翻符号；每条规则带 evidenceRefs沿用项目现有 applyRules() 的有界设计，这是对的，保留
失效条件IC 连续衰减、市场状态切换、样本环境变化 → 自动降权并转回 observing因子拥挤会导致经典因子衰减；经验有有效期，不是永久真理
门槛依据：金融场景方法论 quant-factor-research.md、systematic-strategies.md；项目内 server/journal.js、server/ic.js。

六、「有专业知识的智能体」应该长什么样

结论与上一轮一致并更具体：不引入 LangGraph / CrewAI 等框架（现有后端是零依赖 Node，Python 框架要养第二套运行时），用 Node 内置 fetch 写薄适配器即可。但「专业知识」不靠模型记忆，靠下面这套知识卡。

知识卡：可审计的专业知识载体

卡内容适用条件反例 / 失效条件
K-01
催化预期差		界定事件性质 → 判催化级别（强 / 中 / 弱 / 噪音）→ 看是否已充分定价 → 识别交易结构 → 观察龙头晋级、板块扩散、次日溢价有明确事件锚点且能取到公告 / 新闻时点「预期已充分定价的利好反而是兑现风险」；不把单一新闻上升为长期逻辑；政策映射需真受益
K-02
常见误导信号		单日跌幅大 ≠ 趋势反转；龙虎榜游资追捧 ≠ 值得跟；北向大额净流出 ≠ 必然下跌；利好发布 ≠ 股价必涨每日复盘生成解释时自动挂载多周期确认优先；不做每日涨跌方向预测；不用「必涨 / 必跌」绝对表述
K-03
因子有效性		前向偏差、行业中性化、Z-score 标准化、样本不足不出结论、walk-forward任何假说想过晋升闸门时高回测 IC 不代表实盘可实现；因子数过多易过拟合
来源：金融场景方法论 event-catalyst.md、daily-briefing.md、quant-factor-research.md；均为方法论框架，不含行情数值。

智能体只允许三个动作

  1. 归类：把用户口语复盘映射到固定本体（eventType / gameStructure / expectationGap / outcome），只输出标签，不改任何数字。
  2. 生成待验证假说：从 L0 事实出发生成假说草稿，必须包含可证伪条件与观察窗口；状态一律是 observing，不得直接给 proposal。
  3. 翻译：把确定性计算结果说成人话，数字原样引用、不改口径、不加因果连词。
五条禁止（写进适配器的输出校验）：① 不输出买卖 / 价位 / 仓位结论；② 不写「因为 X 所以涨」这类因果句；③ 无 precommit 时不评判「当时判断对不对」；④ 不生成新因子、不改任何权重；⑤ 未标注来源与时点的网络内容不得作为事实引用。任何输出先过确定性网关：事实账本核对 → schema 校验 → 幂等去重 → 无出处即剔除。

这个定位其实比你原本设想的「专业分析师」更有用：它把用户多年才能总结的隐性经验逼成可登记、可证伪、可积累的结构，而不是替用户生成一个听起来很懂、但无法验证的解释。

七、观察你的习惯：行为账本（不需要 LLM）

这是整套设计里最独特、也最容易做实的一块。行为习惯全部可以从用户自己的操作记录确定性计算，比让模型「分析性格」可靠得多。

指标计算方式用途与边界
处置效应盈利单平均持有天数 ÷ 亏损单平均持有天数只做「习惯镜像」周报，描述不评判
追高倾向实际买入日的 chaseRisk 分位、买入前 5 日涨幅分位可在用户又要追高时提示「你过去 N 次在此区间的平均结果」
计划偏离度实际成交不在 22:00 定格名单中的比例衡量「盘中临时起意」占比
非计划交易占比 / 换手频率无对应定格记录的交易数 ÷ 总交易数票数过多、过度交易本身是风控问题
复盘覆盖率有操作且有复盘记录的天数 ÷ 有操作的天数低于阈值时经验库自动停止归纳，避免样本偏差
选择性记忆复盘中主动记录的反例数 ÷ 事件总数识别「只记对的、不记错的」确认偏误
前置缺口：当前 data/holdings.json 只有 code / cost / shares / note / addedAt，没有卖出记录、买入时点上下文和成交原因，上述指标多数暂时算不出来。需新增 data/journal/trades.jsonl，每次实际动作记一行：ts / code / side / price / shares / planRef / precommitId / note / source=user。这是纯增量文件，不动现有持仓结构。

硬边界：行为账本只做提示与镜像，不直接改评分、不自动惩罚用户。理由同样是防止系统用不可证伪的行为判断反过来影响选股。

八、自我调整的安全边界

  • 冻结基线 v0：现有 stocks.js 评分逻辑永久保留一份只读快照，任何时候都能算出「不用经验会选哪几只」，与当前结果并列展示。
  • 影子模式：所有未采纳经验只在影子表里记录「若采纳，Top12 会怎么变」，不改真实输出。
  • 人工闸门：只有人点 approve 才写 rules.json；AI 不能自己往股池塞票，screened 来源一律先 candidate。
  • 有界回流：沿用现有 ±2 分 / 0.8–1.25 / 不翻符号；每条规则带 evidenceRefs 可一路追到具体 outcome 与真实行情日期。
  • 一键回滚：rules.json 可整体重建（项目已有该能力），采纳错了随时清空回到基线。
  • 失效检测：IC 衰减、市场状态切换、样本环境变化时自动降权并转回 observing；经验有有效期。

十、合规与风险边界

  • 程序化交易边界：只要程序不自动下达委托单，选股、监控、复盘、人工下单、券商条件单均不落入程序化交易定义、无需报备；一旦脚本自动发单，即进入「先报告、后交易」框架。本设计明确停在人工下单之前。（依据：上一轮调研的证监会《证券市场程序化交易管理规定（试行）》相关口径，2024-10-08 施行；具体适用以证监会及交易所正式细则为准，本文不构成法律意见。）
  • 投顾敏感内容：买入时间、连板测算、仓位建议等只作为 Explain 展示，界面保留免责声明，不做收益承诺、不对外提供。
  • 数据使用：行情数据保持个人自用、注明来源与时点、不对外分发；研报与财经媒体属非一手来源，需标注「需核实原文」，不与交易所公告 / 公司年报同等处理。
  • 反幻觉：所有关键数字必须可追溯到「来源 + 时点 + 口径」；数据源缺失时直接写「当前数据源未覆盖」，不得补一组数字再加「待核实」。
  • 界面呈现：A 股语境红涨绿跌；经验结论必须同时显示样本数、置信度与状态（observing / approved / retired）。
