验证层扩充：基本面 · 事件消息 · 逻辑链（v7）

GlobalMarketMonitor 设计文档 · 2026-11-19 · 衔接 v2（Flag 层）/ v3（假说卡）/ v6（冲突闸门）· 零 JS · 仅供研发参考

0. 一句话结论

你指出的问题是准确的：现有验证层只覆盖「价格行为」（T+1/5/20 回填、涨跌、换手），缺三块——基本面（F）、事件消息（E）、事件背后的逻辑链（L）。本版把这三块补进验证体系，并规定：这三块里所有数字走确定性管道、所有因果叙事只能当假说、所有操作结论永不入库；大模型负责抽取和翻译，不负责判断。同时新增一条「外部内容拆解流水线」，让通化金马式的 AI 复盘稿和题材梳理卡都能进系统，但进什么、进哪层、以什么资格进，由流水线说了算，不由稿件说了算。

1. 为什么这三块必须补、且各有各的补法

维度通化金马案例中的体现为什么不能靠现有价格验证正确补法
F 基本面PE(TTM)≈1029 倍*、Q3 归母转亏 −513.24 万*、有息负债超 18 亿*、未分配利润 −22.46 亿*价格验证只能发现「跌了」，不能发现「跌之前就不该按利好买」——估值与业绩背离在 11-13 涨停当天就已经成立财报/估值指标从数据接口确定性直读，形成「估值业绩背离」等 Flag；LLM 禁算任何数字
E 事件消息11-13 医保预期抢跑涨停、11-15 公告 2026-40（支付标准未公布）、11-13 龙虎榜机构净卖出*、融资余额转降*事件的「有没有、何时、说了什么」是事实问题，价格解释替代不了；且公告前抢跑本身就是信号事件卡 + 来源分级（A/B/C）+ 时点记录；公告/龙虎榜/融资做独立管道，事件回贴事实账本
L 逻辑链「利好兑现→资金撤退」「以价换量短期补不回利润」「板块高位集体退潮」「6/25 与 11/15 同剧情演两次」这些是叙事，事后永远能自圆其说；但其中可证伪的部分（重复模式、板块阶段）恰恰是最值钱的信号只做假说卡：机制链 + 证伪条件 + 反例计数；可计算部分（同标的重复模式、板块位置）提取为确定性信号

标 * 的数字来自 C 级稿件（AI 异动分析），入库前须与 2026-10-26 三季报及交易所公开信息逐项核对，核对不过一律置空。

2. 案例拆解一：通化金马五因素复盘稿

这份稿件是「其他智能体生成」的 C 级内容，但它混合了三种不同资格的内容。系统的正确反应不是整篇接受或整篇拒绝，而是逐条拆解分流：

稿件内容性质去向处理方式
医保目录公告（乙类、协议期 2027-01-01 至 2028-12-31、支付标准未公布）可核对事实L0 事实账本已与深交所公告 2026-40 原文核对一致（前次已核），带来源时点入库
三季报数字（营收 1.79 亿/-25%、归母 −513.24 万 等）可核对事实（未核）L0 待核对置「需核实原文」，与财报接口复算比对后才准入账本
支付标准未公布 / 协议期 2027 才执行事前可观测Flag买入前即可查的确定性信号，不改分，T+1/5/20 回填校准
6/25 与 11/15 同一模式（抢跑→兑现→连跌）事前可观测Flag同标的 6 个月重复模式可程序化检测（v2 已定义 repeat_pattern_6m），这是全案最值钱的一条
估值业绩背离（PE 千倍 vs 由盈转亏）事前可观测（依赖未核数字）Flag数字核实后自动可算；核实前只显示「据 C 级稿件，未核实」
龙虎榜游资接机构跑 / 融资盘止损事前可观测（未核）Flag接龙虎榜/融资数据管道后确定性生成；稿件数字仅作线索
「利好兑现→资金撤退」「以价换量补不回利润」「板块高位退潮」因果叙事假说卡转成带证伪条件的假说进待审区：如「利好兑现型标的在支付标准落地前 20 日跑输行业」——可被数据投票
「不接飞刀」「持有的不补仓」「只做放量回封的短线」操作结论丢弃系统永不生成、永不采纳。这是人（或别的智能体）的判断，不是可验证事实
「12.04 元现价」「今天 11/18」已过期/已证伪丢弃前次已核：12.04 是 11-18 开盘价非收盘价（收盘 12.03）；稿件停在 11-18，11-19 已收 11.07（-7.98%），盘中触及 10.83 未封住——稿件内容过时一天即失效
关键校准：五重因素 ≠ 五个原因。稿件把「三季报转亏、债务压力、板块退潮」这些买入前就公开存在的静态背景，事后组织成了「下跌的原因」。系统的 F/E/L 分层正是为了在时间轴上区分：事前就有的（背景/风险）→ 进 Flag；事后才知道的（跌了）→ 进行情回填；中间的因果跳跃 → 只能当假说。11-18 异常波动公告 2026-41 确认公司无未披露重大事项——事件落地后并没有新增基本面利空，这更说明「五因素」多数是事前背景而非事后新因。

3. 案例拆解二：题材梳理卡（液冷算力+华为+多媒体视讯）

这张卡是市场上广泛流传的「题材梳理」形态，它的特点是自带来源锚点（每条都写了据何日年报/互动易），这使它比通化金马稿件更接近可核实素材——但也三个坑：

卡中条目引用来源来源等级处理
泵驱两相冷板液冷、PUE 1.1 左右、与航源光热/广电五舟联合研发 8 卡液冷服务器2026-08-27 半年度报告A 候选定位半年报原文对应章节核对后才升 A；「PUE 1.1 左右」「联合研发」属定性表述，核对时确认原文是否真有此表述
「公司与华为保持多年合作，是华为的金牌经销商」2023-03-02 互动易需核实互动易是公司回复口径，非审计信息；「金牌经销商」资质须查华为官方认证体系；且引用的是 2023 年信息，距今近 3 年，须确认现时仍有效
签约马栏山智算、广西北投、甘肃福彩、南昌电信、南通智算，部分已交付验收2026-05-18 互动易需核实「部分项目已交付验收」无验收证明；签约≠收入，逐条核实前只作线索
主营多媒体视讯、国产化、长期服务部委与央企客户2026-04-09 年度报告A 候选年报原文核对；「长期服务」等表述按原文收录
题材卡的第一道门：标的绑定。这张卡没有股票名称和代码——市场上大量题材卡都是匿名流传的。无标的的内容无法做任何验证（没有行情、没有财报、没有公告可查），所以一律先入素材库（material-library），由用户手动绑定标的（或确认「与此无关」）后才进入拆解流水线。系统不得自行猜测「这是哪只票」——猜错会把整卡内容错挂到无关标的上，污染其事实账本。

题材卡的正确价值定位：它是「事前素材」而非「验证材料」。绑定标的后，它的价值是让系统在题材发酵早期就建立「该标的存在这些待核实主张」的台账；随后每条主张按来源逐条核实，核实通过的进事实账本，与行情/财报数据交叉出现矛盾时（如「签约用户众多」但财报应收账款/合同负债无变化）自动生成叙事与数据的冲突条目，走 v6 的冲突处置。

4. F/E/L 三层定义与数据契约

4.1 F 基本面层（fundamentals.jsonl）

项约定
数据来源财报/行情数据接口确定性直读（复用现有 sources.js 的多源兜底模式）；LLM 禁止计算任何财务数字
指标范围（首期）PE(TTM)/PB、归母净利润及同比、扣非净利润、营收及同比、有息负债、货币资金、未分配利润、连续亏损年数、分红记录
派生信号估值业绩背离（PE 分位 vs 业绩方向）、由盈转亏、连续三年未分红、高有息负债 + 由盈转亏叠加 → 生成 F 类 Flag
验证方式F 层信号不做 T+1/5/20 回填（它不是时点信号），而是做截面命中率统计：带此 Flag 的票在后续 20/60 日相对行业超额的分布
智能体边界LLM 只做「指标异常解读」（如把由盈转亏翻译成一句人话），解读文字带 code 引用，数字一律引用接口值

项约定

5. 外部内容拆解流水线

无论输入是粘贴的复盘稿、截图题材卡还是对话内容，统一走五步：

  1. 绑定检查：无标的 → 素材库待绑定；有标的 → 进入下一步。
  2. R1 抽取：智能体抽取「主张/证据/来源/时点」四元组，逐条预判来源等级；禁补数字、禁改写数字、禁合并条目。
  3. 确定性网关：schema 校验、出处核查（无来源即剔除）、幂等去重（同一主张重复粘贴不重复入库）、数字核对（C 级数字与接口复算比对，不一致标 conflict）。
  4. 四路分流：可核对事实 → L0 账本（核对后才算数）；事前可观测 → Flag；因果叙事 → 假说卡；操作结论与过期内容 → 丢弃区（保留原稿可查，永不生效）。
  5. 反馈回填：Flag 走 T+1/5/20 与假警报率台账；假说卡走 support/contradict 累积；一切结果回写账本供冲突处置（v6）与画像校正（v3）使用。
幂等与去重：通化金马这份稿件你可能从多个渠道反复见到（你已是第二次贴入）。流水线按「symbol + 事件类型 + publishedAt + 主张哈希」做幂等键，重复内容只更新 capturedAt 与核实状态，不产生重复 Flag。

6. 智能体与大模型的边界（F/E/L 三层专项明确）

角色F 基本面层E 事件消息层L 逻辑链层
R1 抽取不做（接口直读）抽四元组 + 来源等级预判（公告=A、互动易=定性需核实、稿件=C）从叙事中抽出可证伪的机制链骨架
R2 假说把 F 信号组合成「背景画像」（如高位+转亏+高负债）供假说引用把事件序列组合成「事件链」候选生成带证伪条件的假说卡；每日每标的最多一条主假说
R3 分拣稿件数字与接口复算不一致 → 标 conflict事件时点与叙述时点矛盾 → 标 stale/conflict竞争假说并列展示，禁裁决、禁折中合成
R4 教练把财务异常翻译成人话（引用接口值）把事件时间线画成人能看懂的序列把机制链讲成「系统是这么看的，依据是这些，错了会表现为那个」
共同禁令禁计算/修改任何财务与行情数字；禁给买卖结论与仓位建议（「不接飞刀」式话术永不生成）；禁把叙事当事实互相佐证；禁跳过来源直接采信；产物永远是待审提案，默认动作恒为「不改任何东西」

大模型接入延续 v5 结论：DeepSeek（OpenAI 兼容，thinking=False 做结构化抽取，空白 content 兜底重试，MODEL_ID 走配置），先以 Node 薄适配器形式接 R1/R4 两个低风险角色，R2/R3 待样本积累后经 LangGraph sidecar（Pydantic AI）升级——升级只是换编排方式，边界规则不变。

7. 与既有层的衔接

既有层衔接点
v2 Flag 层F/E 两层产出的就是 Flag 的新来源；Flag 三级（提示/警示/强警示）沿用；「同标的 6 个月重复模式」由 E 层事件卡驱动，从人工发现变自动检测
v3 假说卡/四层账本hypotheses.jsonl 即 v3 的 L2 统计性假说层的载体；L0 事实账本由 fundamentals + event-cards 充实；晋升阶梯与门槛不变
v6 冲突闸门「叙事 vs 数据」是新增冲突类型：题材卡主张与财报矛盾、稿件数字与接口复算矛盾，走 v6 四层处置（确定性重算 → 结果投票 → 智能体翻译 → 用户偏好），默认「以后再说」
v6 录入/对话粘贴复盘稿 = 录入表单的「粘贴模式」；题材卡截图走同一 OCR + 抽取入口；对话中的外部内容分享同样进流水线
