回流边界已在代码里写死（stocks.js:607-629）：只作用于涨停结构修正、单股最多 ±2 分、乘数 [0.8, 1.25]、不翻转符号；无规则时乘数为 1，链路与原先完全一致。当前 rules.json count=0，故经验实际尚未影响任何一次评分。

二、经验知识库与整体架构的关系

定位一句话：经验库是并联旁路 + 只读知识层，不是串联决策层。它在架构上有两个身份，必须分开，否则会误以为「经验越攒越准、能接管选股」。
身份内容通向哪里关闭后果
① 有界旁路事实账本 → 归纳 → 待审 → 闸门 → 规则投影 rules.json唯一写路径：以乘数微调「涨停结构」这一项修正（±2 分）乘数回到 1，stocks.js 与原先完全一致
② 只读知识层个人手记 / 对话归档 / Flag 风险提示 / 并列假说 / 反例库 / 市场状态解释卡只进界面、复盘页与提醒文案；没有通向评分的写路径提醒与解释消失，评分不变

这个分层解释了前面几版的一个表述偏差：v1 说「经验回流闭环走通才算数」，其实那只覆盖身份 ①；而你这轮说的「提醒、风险提示、归纳、观察习惯」绝大部分属于身份 ②，它们本来就不该改分。用户价值主要来自 ②，风险控制主要来自 ① 的克制。

2.1 为什么必须并联而不是串联

  • 可审计：旁路可整体一键关闭并做 A/B 对照（冻结基线 v0 永久保留），串联层一旦污染无法分离。
  • 可证伪：经验是少量样本上归纳出的假说，市场非平稳；只有以「有界乘数」形式并联，才能用真实行情逐条检验它是否还有用。
  • 非专业用户可安全使用：旁路默认空、默认不改变任何结果，用户即使完全不操作，系统也不会变坏（见第六节）。

架构其余部分沿用 v4/v5 结论：8777 零依赖 Node 主服务不动；确定性计算层（Gate / Score / Flag / 四象限 / 冲突重算）在主服务内；Python sidecar 只做受限抽取与翻译，挂掉时主服务照常选股；MCP / 技能只提供现成数据与知识卡，不训练模型。

渠道现状入库方式默认落点

② 个人手写录入缺写管道结构化四要素表单，口语由智能体抽取、原文永久保留待审经验区，标 source: manual

3.1 手写录入：四要素 + 事前预判

不要做「一个自由文本框直接写进库」。每条个人经验必须带齐以下字段，缺任一项只允许存为「草稿」、不得进入待审队列：

字段含义为什么强制
claim我观察到了什么（一句话，不写因果）避免「因为 X 所以涨」式不可证伪叙事
falsifyCondition出现什么现象算我错没有证伪条件的复盘只是故事（v2 结论）
scope适用行情 / 票种 / 持有周期 / 个人画像标签同一条经验对不同交易风格含义相反
precommit结果出来之前，我当时怎么想、打算怎么做唯一能把「利好出货 / 提前布局」变成真经验的办法
sourceRef + asOf来源与系统时间戳所有关键内容可回溯；时间由系统写，不接受手填

3.2 对话内容能不能进知识库：能，但三级隔离

  1. 原文层：conversations.jsonl 只追加、可回溯、可删除，带 sessionId 与「本轮不记录」标记。对话原文不是经验。
  2. 抽取层：智能体把口语拆成「主张 / 证据 / 来源 / 时点」四元组，标 user_note、sourceGrade: C；抽取结果不进事实账本。
  3. 候选层：只落待审经验区，与自动归纳的条目共用同一条晋升闸门。
为什么对话里的数字要一律置 null：用户自己复述的数字、日期、结论是全部来源里最软的一层。v2 核过的通化金马案例中，「12.04 元」被当成 11-18 收盘价，实际是当日开盘价；该案例的财务、龙虎榜、融资数字来自其他 AI 稿件，均未与三季报及交易所原文核对。对话能贡献的是「我当时为什么买」这类意图事实，不是行情事实。

四、智能体自动读取、分类、新建因子：边界在哪

一句话：自动归类可以，自动生效绝对不行。智能体可以把「我发现放量突破后第二天经常回落」判为经验候选、把「把换手率分位数登记成因子」判为因子候选，但两者都只能落到待审/影子区。
动作能否自动约束
读取已有经验与因子、贴标签、发现语义重复可以确定性分诊先跑，模型只给建议不得覆盖；低置信度进「待澄清」不猜（沿用 interaction.js 现有规则）
把新经验写入待审队列可以必须带幂等键、原文、来源时点；status: pending、affectsScore: false
把经验转成 Flag 风险提示半自动默认推荐路径。先影子运行（只显示不算分），累计反馈后再决定是否升级
把经验转成新因子 / 改权重不可以必须过统计闸门：字段白名单校验 → 影子运行 → Rank IC 复检（IC>0.03 且 IR>0.5）→ 样本外不劣化 → 人工最终否决 → 有界上架
写入事实账本 / 下单禁止事实账本只收行情与核实后的一手来源；系统全程不自动下达委托单

项目里 web/navplan.js 已经写好了上面那条因子状态机并注明「复用现有 ic.js」，所以不需要重新设计，只需要把设计态落成代码。另有一条纪律要写进产品默认值：按 quant-factor-research 的方法论，5–10 个能验证的强因子优于 30 个弱因子；因此智能体抽取到新经验时，默认建议是「存成 Flag 提示」，不是「新建一个因子」，只有当同类样本反复验证、且现有因子无法解释时才提出因子候选。

为什么不让模型直接判「这条该不该变因子」：模型没有你的真实持仓、没有未来行情，也不会做样本外检验。它能做的是整理语言与发现相似，判有效性是 ic.js 与真实行情回填的职责。这也是 v5「零训练四层能力栈」的延续 —— 专业能力靠现成 MCP 数据工具 + 可溯源技能卡，个人经验靠可读可改可删的 JSONL 账本 + 检索增强 + 有界回流，连经验池也不做微调。

五、因子与经验冲突：现状、处置矩阵、非专业用户闸门重构

5.1 现状：没有冲突机制，而且人工闸门设计有误

  • 代码中不存在因子/经验冲突检测；auditLesson() 只有 approve / reject，reviewer: 'user'，界面只显示 claim + evidence(n / hitRate / avgRet / avgExcess / payoff) + confidence（后者只是 n≥40 / ≥20 的样本量标签，不是统计置信度）。
  • 没有反例数、没有证伪条件、没有历史校准、没有智能体建议 —— 让非股票研究人员判断「这条统计规律是否成立」是不可执行的设计。v1–v5 把这道闸门称为「人工审核」，隐含了一个不成立的假设。

5.2 冲突四分法与处置矩阵

冲突类型例子谁来解决输出
事实 / 口径冲突叙述说 11-17「低开高走」，日 K 为前收 3602.57 / 开 3585.67 / 收 3584.58；两市成交额 vs 沪市单市场成交额确定性重算（代码）标注 narrative_conflict / scope_conflict，模型不参与
方向冲突因子打分 77「重点关注」，经验 Flag 提示同类形态历史偏空并列呈现 + 结果验证投票两条都显示，各自带样本数、反例数、来源时点；系统不裁决
解释冲突同一天出现两种「为什么涨/跌」的假说并列假说卡，各自带证伪条件每日最多一个主假说，禁止折中合成第三种解释
价值冲突系统提示风险，但你的买入理由是医保准入用户（偏好判断）只决定「这条提醒我要不要继续看」，不判定谁对

5.3 闸门重构：把专业判断从人身上卸下来

层机制负责什么需要用户吗
①确定性重算事实、口径、时点冲突由代码裁定；超 T+1 标 stale不需要
②结果验证投票复用 barOf() / benchRet() 回填 T+1 / 5 / 20、20 日最大回撤、超额；累计「这类冲突下谁更常对」与假警报率；反例写 counterexamples.jsonl不需要
③智能体 + 技能把两边依据、样本数、反例数、不确定性翻译成人话，给带置信度的建议；禁止裁决、禁止合成、禁止改写数字不需要用户判对错
④用户偏好「保留提醒 / 关掉这条 / 以后再说」—— 判断的是提示对我有没有用只需判断有用没用
默认动作恒为「什么都不改」：④ 的默认项是「以后再说」。用户长期不点、点错、甚至完全不懂股票，系统状态都不变坏；误判的代价从「污染评分」降为「少看一条提醒」。

「结果验证」和「智能体+技能」不是二选一：结果验证负责最终谁对（慢，几周到几个月，统计性，可证伪）；智能体+技能负责现在怎么看懂（快，翻译，带不确定性）；用户负责我要不要看这条提醒（偏好，随时可改）。只有结果验证，当下看不懂提醒；只有智能体，会变成听模型的话；只有用户，就是现在的死结。

5.4 唯一还需要人的场景：晋升改分

让一条经验从 Flag 晋升到 Score（改分）仍需人工确认，但门槛不由人把守：n≥30、IC>0.03、IR>0.5、样本外不劣化、一次只登记一个主假说、影子验证先行。人只做最后一道否决，且界面默认按钮是「暂不采纳」；通过后仍受 ±2 分 / 乘数 [0.8, 1.25] / 不翻符号约束，冻结基线 v0 永久保留作对照。

5.5 审核按钮的新语义

旧按钮（现状）新按钮
采纳并回流 / 驳回保留提醒 / 关掉这条 / 以后再说（默认）
