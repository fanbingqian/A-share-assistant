3｜方案内部张力检查（3 处已化解、2 处需求本身有张力）

已化解但必须写进网关规则，否则会回退

  • 「给建议」vs「禁买卖建议」：已用「需关注 X / 若 Y 则 Z」话术化解 → 缺一张可校验的话术规则表（禁词清单 + 必带字段），当前只是文档纪律。
  • 「复盘结果入库」vs「precommit 才可采纳」：已在 v9 分为两链路（经验链路不改分、因子链路过 IC 闸门）→ 闸门代码未写。
  • 「感知频率」vs「成本/限流」：已用 diff + 冷却 + 日上限化解 → watchers 未建，参数未定。

需求本身的张力（无法完全消除，只能明确取舍）

  • 「实时」vs 公告/数据源的固有延迟：交易所公告挂网本身有延迟，观察者轮询 10 分钟是务实值；「实时评估」应定义为「盘中监控即时 + 公告感知分钟级 + 复盘盘后」，不要承诺秒级。
  • 「因素全面」vs 小样本过拟合：已用四用途拆解（Gate/Score/Explain/Flag）化解，但要守住「5–10 个强因子优于 30 个弱因子」——这条在实现时最容易破防。
