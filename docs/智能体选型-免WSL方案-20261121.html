智能体选型：免 WSL 方案筛选

筛选日期 2026-11-21 · 场景：GlobalMarketMonitor（Node 零依赖 8777 服务 + DeepSeek + 本地账本）· 目标：一个能贯穿五个模块的核心智能体

先纠正一个前提

需要 WSL 是 Hermes Agent 的个别限制，不是智能体框架的普遍要求。官方 Hermes（Nous Research，Python）在 Windows 上是实验性支持、官方推荐 WSL2，所以我们之前卡住了。而下面这些框架，绝大多数在原生 Windows 上直接可跑：

  • Node/TypeScript 系（Mastra、DeepSeek Harness）——本来就是跨平台，和你现有 8777 Node 服务同栈，最容易贯穿全部模块。
  • Python 系（Pydantic AI、LangGraph Python、AutoGen）——常规 pip install 即可，不需要 WSL；但要跨进程桥接到 Node。

当前事实：你的系统已经在用 DeepSeek 兜底跑通了全部五个模块（对话已能引用真实量能数据）。所谓"Hermes 核心"目前缺的只是一个正式框架外壳（持久记忆 / 技能 / 工具编排），不是缺一个能说话的模型。

推荐一：Mastra（首选，替换 Hermes 的核心位置）

为什么它最合适：你的服务是 Node.js，Mastra 也是 TypeScript/Node，可以直接嵌进现有进程，不需要 WSL、不需要 Python、不需要另起服务。五模块要的"贯穿"靠它原生的 memory（对话历史 + 工作记忆 + 观察记忆）、workflow（日历提醒/15分钟播报/选股流水线）、MCP（接外部工具）、evals/可观测（低幻觉校验）正好覆盖。

DeepSeek 接法（官方文档写法）：

import { Agent } from '@mastra/core/agent';

const agent = new Agent({
  id: 'gmm-core',
  name: '市场分析核心',
  instructions: '只依据注入的数据快照回答，禁止编造数字…',
  model: {
    id: 'custom/deepseek-chat',
    url: 'https://api.deepseek.com/v1',
    apiKey: process.env.DEEPSEEK_API_KEY
  }
});

代价：需要引入 npm 依赖（不再是严格零依赖），改造量集中在 server/hermes.js 一个适配器文件；现有 agent.js 的确定性网关（禁编造数字、拦截买卖建议）可保留，作为 Mastra 输出后的校验层。

推荐二：DeepSeek Harness（官方备选，适合做"第二个智能体"）

DeepSeek 官方 2026-10 开源的通用 agent runtime，MIT，npx @deepseek-ai/dsh web 即可在 Windows 原生启动，Web UI 在 127.0.0.1:3080，加 --no-open 可后台跑。插件化架构、支持技能与 MCP、本地优先。

但官方 README 明确写着："developer preview … THERE WILL BE COMPATIBILITY-BREAKING CHANGES"，并要求运行前阅读 SAFETY.md。它定位是通用任务/编码 agent，不是可嵌入业务系统的库。建议作为备选智能体实例桥接，别把五个模块的地基押在它上面。

推荐三：Pydantic AI（低幻觉专项 / 验证层）

官方文档明确支持 DeepSeek：OpenAIChatModel(model_name='deepseek-chat', provider=OpenAIProvider(base_url='https://api.deepseek.com', api_key=...))。它的强项是结构化输出 + Pydantic 校验 + 校验失败自动让模型重试 + typed tools + evals——正好是你要的"减幻觉"。

定位建议：不做总入口（跨 Python→Node 桥接增加复杂度），而是做需要严格结构化输出的专项校验子智能体，例如事件影响判级、经验入库抽取、复盘简报字段校验。也可以和现有 Node 网关二选一：现在网关是手写的，Pydantic 是成熟库版。

关于 OpenClaw（用户追问）

结论：它确实免 WSL，但定位和你这个项目是两回事，不建议当核心智能体。

OpenClaw（前身 ClawdBot/MoltBot，OpenClaw Foundation 维护，MIT，约 39 万星）是自托管的个人 AI 助手 Gateway：一个本地进程连接 Discord / Telegram / WhatsApp / 企业微信 / 飞书等 20+ 聊天渠道，让你可以在手机聊天软件里指挥它干活。它的强项是技能市场（ClawHub 数千技能）、持久记忆、cron 定时、webhook、多智能体路由。

  • ✅ 免 WSL：官方给了 Windows PowerShell 一键安装 iwr -useb https://openclaw.ai/install.ps1 | iex，不需要 WSL2。
  • ✅ 支持 DeepSeek：模型是可换的插件，DeepSeek / Claude / GPT / 本地模型都能接。
  • ❌ 不是可嵌入的库：它是独立 Gateway 进程 + 聊天渠道架构，不是给你 8777 服务当大脑调用的库。要集成得另起进程 + 协议桥接，比 Mastra 复杂得多。
  • ❌ Node 版本不够：官方要求 Node 24.22.1+ 或 26.x（推荐 26），本机是 22.22.2，需先升级 Node（现有服务在 22 上跑得好好的，升级有兼容风险）。
  • ⚠️ 交互外壳冲突：它的交互入口是聊天软件 + 自带 Control UI，而你已经在做浏览器右侧常驻对话。两套对话入口并存，体验割裂。

唯一真正有价值的位置：解决缺口清单里那条「系统级弹框提醒」——用 OpenClaw 的 cron + 聊天渠道，把日程事件提醒、量能播报、告警推到手机微信/Telegram。这是它比浏览器通知更实用的地方。可作为独立的提醒通道旁路接入，不碰核心智能体。

来源：OpenClaw 官方文档（docs.openclaw.ai）与官方 GitHub README（MIT；"One Gateway runs it as a personal claw …"；Windows PowerShell 安装命令；Node 26 推荐 / 24.22.1+ 最低）。

关于 Codex（用户追问）

结论：免 WSL，但它是「编码 agent」，不是业务系统的智能体内核，不适合。

Codex 这个名字下有三样东西，别搞混：

  • Codex Web：OpenAI 云端 agent（chatgpt.com/codex），闭源服务，数据在云端，与你「本地存储、本地知识库」的要求冲突。
  • Codex CLI：开源（Apache-2.0，13.6 万星）的终端编码 agent，Rust 编写，原生 Windows（irm https://chatgpt.com/codex/install.ps1 | iex 或 npm i -g @openai/codex）。原生只认 ChatGPT 账号 / OpenAI API key；要接 DeepSeek 得挂第三方协议代理（如 cliproxy-rs），把 Responses API 翻译成 Chat Completions——多一层故障点。
  • Open Interpreter：Codex CLI 的 Rust 分支（Apache-2.0，6.8 万星），原生支持 DeepSeek/Kimi/GLM，还能切 harness。但它依然是终端编码 agent，定位是「帮你写代码/改文件」，不是「贯穿五个业务模块的分析内核」。

共同硬伤：①不是可嵌入 Node 服务的库；②核心能力是读写代码和执行命令，而你的智能体要的是读数据快照、做低幻觉分析、不执行任何交易动作；③交互入口是终端/IDE，和浏览器右侧对话割裂。把它们当核心，等于让一个「程序员」去当「分析师」，还多一层 WSL/代理/Node 升级的风险。

来源：openai/codex 官方 GitHub README（Apache-2.0、"Lightweight coding agent that runs in your terminal"、PowerShell/npm 安装命令）；Open Interpreter 官方仓库与公开评测（Codex Rust fork、DeepSeek 支持、0.0.x 版本）；cliproxy-rs 文档（Codex→DeepSeek 需 Responses→Chat Completions 协议转换）。

落地建议（不推翻现有成果）

  • 把 server/hermes.js 改造成可切换后端：mastra（默认） / dsh（DeepSeek Harness 桥接） / wsl-hermes（原方案保留） / direct（现有 DeepSeek 兜底）。配置写在 data/config.json，前端状态栏显示当前后端。
  • 第一阶段只接 Mastra，保留 direct 兜底；五个模块的 API 与前端一行不用改，因为都走同一个 hermes.chat() 入口。
  • 确定性网关（禁编造数字 / 拦截买卖建议 / 来源锚点）继续放在 hermes.js，不管底层换成谁都强制过闸。
  • 若后续要严格结构化输出，再并接 Pydantic AI 作为专项服务；若想要"桌面级智能体"，再桥接 DeepSeek Harness。

需要你拍板：是否按首选 Mastra 接入？确认后我直接改 hermes.js + 配置 + 状态显示，其他模块不动。OpenClaw 若要用，建议只做「手机提醒通道」旁路，不替换核心。
