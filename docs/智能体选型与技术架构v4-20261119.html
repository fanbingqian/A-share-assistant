智能体选型与技术架构 v4

项目：GlobalMarketMonitor · 文档日期：2026-11-19（周四，盘后）· 承接 v1 智能体选型 / v2 风险提示层 / v3 双向经验与市场状态 · 状态：设计稿，未改动任何现有代码或数据文件
四句话结论。① 选哪个：复盘链路用 LangGraph（库，MIT）+ Pydantic AI（MIT），跑成独立 Python sidecar，自己用 FastAPI 包一层，绝不用官方 Agent Server；判断链路永远不引入 LLM。② 智能体做什么：不是「懂股票的助理」，而是四个受限角色（抽取 / 假说 / 分拣 / 翻译）＋一个可暂停可回放的状态机，产出物永远是待审提案。③ 架构：现有 8777 零依赖 Node 主服务保持不变，新增「确定性层 → 只读 sidecar → 确定性网关 → 人工闸门 → 有界回流」五段。④ 闭环：专业性与个性化都能闭环，但闭环目标是提示校准，「经验 → 胜率」这一环在小样本、非平稳市场里统计上不可闭环，不能设为系统目标。

零、先澄清一个被绕了三轮的问题

前三版一直说「不引入框架」，而你要的是「入驻的智能体」——这两个说法看似矛盾，其实在说两条不同的链路：

链路做什么对 LLM 的态度前三版的结论
判断链路选股评分、Gate 剔除、Flag 触发、四象限标注、事实口径冲突裁定禁入 全部确定性计算，可复算、可回溯「不引入框架」指的就是这里，结论不变
复盘链路口语复盘归类、假说生成、冲突语义分拣、结果翻译、经验晋升编排受限进入 只产提案，不产结论前三版只给了「薄适配器」，没有正面回答选型 —— 本版补上
为什么之前不敢直接给框架名：在样本 18/30、待审 4 条、复盘流程单步就能跑完的时候，上状态机是过度设计，还会带来第二套运行时和进程通信成本。但「什么时候该上」必须有明确条件，否则就变成了回避问题 —— 见第一节的触发条件表。

一、选型：LangGraph ＋ Pydantic AI，以及一条许可证修正

1.1 单选结论

编排层 LangGraph（Python 库，MIT）
把「事前登记 → 影子验证 → 待审 → 人工审核 → 有界回流 → 失效退役」画成显式状态图。interrupt() 在「写入知识库之前」暂停，Command(resume=...) 跨天续跑；SqliteSaver 把 checkpoint 落在本地，durability="sync" 适配可能等几天的审批。三个月后可以加载任意历史 checkpoint 回放「我当时为什么这么判断」。
单步层 Pydantic AI（MIT）
用 Pydantic 模型强制「主张 / 证据 / 来源 / 时点 / 证伪条件」字段不缺失；requires_approval=True 的 deferred tools 天然适配「AI 跑完 → 我下班后审 → 明天继续」；OpenTelemetry 原生，trace 落到自己的存储，不绑定任何商业控制台。
对前版结论的修正（重要）：v1 写的是「LangGraph（MIT）做成独立 sidecar」，这个说法不够精确。核实结果是 —— LangGraph 库、checkpointer、CLI、SDK 均为 MIT，但官方 Agent Server（HTTP 服务化）是 Elastic License 2.0，自托管生产需要 LangSmith 许可密钥。因此架构必须写成：只装库，自己用 FastAPI 包一层 HTTP 接口，完全不用 Agent Server，这样整条链路保持 MIT、无商业许可依赖、无托管平台绑定。
来源：Geekflare《LangGraph review》、WTF Radar《LangGraph Review: Durable Agent Graphs for Production》、LangGraph 官方 persistence / interrupts 文档，经 domain_search 于 2026-11-19 检索；第三方评测为非一手来源，许可证条款需以官方 LICENSE 原文核实。

一条比选型更重要的实现约束：这六个框架没有一个是「持久执行 = 恰好一次」。LangGraph 恢复时被打断的节点会从头重跑，CrewAI 任务重跑，Pydantic AI 的引擎是 at-least-once，OpenAI SDK 官方明说审批不保证恰好一次。因此所有外部写入（知识库、rules.json、flag-events.jsonl）必须带幂等键，例如 reviewId = date + symbol + ruleId + version；同一次复盘的结论重复写入不能产生重复记录。所有写库副作用放在 interrupt() 之后，或做成幂等。

二、智能体到底做什么：逐项职责清单

「智能体」在本系统里不是一个有人格的助理，而是四个受限角色 + 一个编排器 + 一道网关。每一项都必须能回答「输入什么、输出什么、禁止什么、怎么校验」。

角色输入输出禁止校验方式
R1 结构化抽取员
LLM · Pydantic AI		你的口语复盘、公告原文、媒体稿件（标来源等级）「主张 / 证据 / 来源 / 时点」四元组 JSON；缺字段直接拒绝禁止补数字、禁止改写数字、禁止把 C 级线索写成事实Pydantic schema 强类型；来源为 C 级时数字字段一律置 null
R2 假说生成员
LLM		事实账本 + 可溯源知识卡（催化预期差 / 常见误导信号 / 因子有效性）带证伪条件的待验证假说卡；每天最多一个主假说禁止写「因为 X 所以涨」、禁止给买卖结论、禁止一次生成五个原因证伪条件非空；supportN / contradictN 必填；反例库强制关联
R3 冲突分拣员
LLM 只做语义		两条互斥叙述冲突类型标签：fact_scope_conflict / interpretation / stale / value禁止裁决谁对、禁止合成第三种解释；事实与口径类冲突一律交确定性重算覆盖类型必须在枚举内；事实类标签出现时网关强制走重算
R4 教练翻译员
LLM		确定性计算结果 + 个人画像人话提示 + 按画像的提示排序与措辞禁止改分、禁止新增判断、禁止出现「别买 / 不接飞刀」等操作建议提示语白名单模板；输出不含数字变更；画像只影响展示
编排器
LangGraph		上述四角色 + 人工答复状态机：precommit → 影子验证 → 待审 → interrupt() → 有界回流 → 失效退役禁止自主循环、禁止无人审核即写库checkpoint 本地 SQLite；OTel trace 落自有存储；幂等键
确定性网关
Node · 零 LLM		智能体全部输出通过 / 剔除后的待审提案禁止直接改评分、禁止直接入池schema 校验、事实账本逐条核对出处、幂等去重、无出处即剔除
专业知识从哪来：不靠模型参数里的记忆，靠可溯源的知识卡（每张卡带机制链、可观测指标、证伪条件、来源与版本）。智能体只是把知识卡与当日事实做匹配，卡本身由你审、可版本化、可退役。这样「股票专业性」是可维护的资产，而不是每次调模型碰运气。

四、逻辑闭环：能不能做到「股票专业性 + 个人经验个性化」

能，但需要把「闭环」拆成三个可验证的环和一个明确不可闭环的断点。如果目标是「判断越来越准」，这个系统注定失败；如果目标是「该看见的别漏、提示越来越贴合我、错误不重复犯」，闭环是成立的。

环 1 · 专业性
可闭环

事实 → 可复算 → 可证伪 → 有界回流。每个数字带来源＋时点；冲突交确定性重算；知识卡可版本化与退役。

指标：IC / IR、样本外劣化、出处覆盖率

环 2 · 个性化
可闭环

行为 → 画像 → 提示排序 → 反馈 → 校正。画像只改展示不改分，判错也不伤本金，所以闭环成本低、可反复试。

指标：提示点开率、忽略率、画像与行为一致率

环 3 · 校准
可闭环

Flag → T+1/5/20 回填 → 反例计数 → 升降级 / 退役。反例库常驻，防止确认偏误。

指标：风险回避价值 与假警报率并列

断点 · 「经验 → 预测准确率」不可闭环：现有样本 18/30，个人样本天然小；市场非平稳，规律会漂移；多维度切样本存在多重比较，校正后大多不显著；且无法对个人做样本外双盲验证。任何「我的经验让胜率提高了」的表述都不可证伪。替代目标：① 降低「可预见错误的复犯率」（同一 patternFamily 再次踩坑的比例）；② 提升提示校准度（强警示之后确实出现不利结果的比例，同时控制假警报率）；③ 提高复盘覆盖率与事前登记率。把这三条写进界面，比选哪个模型更重要。

4.1 个性化为什么不能靠模型猜

同一条「高开低走」对隔夜短线是强警示，对长线定投可能只是噪音。所以 profile.json 分两块：declared 是你显式声明的周期 / 风格 / 风险偏好，inferred 是从 trades.jsonl 确定性算出的实际持仓周期、买点分位、仓位集中度、计划偏离度。两者冲突时以行为为准（conflictPolicy: behavior_wins），画像只影响提示显示与排序，affectsScore: false 是硬约束。前置缺口：现有 holdings.json 没有卖出记录与买入时点上下文，需新增 trades.jsonl（纯增量，不动现有结构）。

4.2 专业性与个性化如何相乘而不互相污染

两者在架构上不共用一条写入路径：专业性走「知识卡 + 确定性计算 + 有界回流」，最终可能微调分数；个性化走「行为账本 + 提示排序」，永不写分数。交汇点只有界面右栏：同一条 Flag，对不同的你显示不同的顺序与措辞，但触发条件与样本数完全一致。这样个性化带来的错误不会影响判断链路，也就不会出现「因为我是短线所以系统替我看空」这种污染。

5.1 PC 端使用习惯的具体约定

  • 宽屏优先：≥1440px 三栏全展开；1180px 以下证据栏自动移到下方，不横向滚动。
  • 来源时点悬停即见：任何数字都能在悬停或右栏看到「来源 + 取数日 + 口径」，不跳转、不新开页。
  • 键盘：/ 聚焦录入 / 搜索，Esc 收起右栏；审核用二次确认（按钮就地变「确认？」），不弹模态，避免打断连续复盘。
  • 颜色：红涨绿跌（A 股习惯）；Flag 用琥珀 / 橙 / 红三级，与涨跌色分开，避免误读为买卖信号。
  • 离线可用：零 CDN、零第三方字体、零外部脚本；原型含约 70 行内联 JS 仅用于演示交互，产品实现仍以现有 .iw- 体系为准。
  • 一键降级：顶栏「智能体层」开关关闭后，界面只显示确定性结果，待审提案区隐藏 —— 任何时候都能退回纯量化模式。

七、风险与合规边界

  • 程序化交易：只要程序不自动下达委托单，回测、信号、人工下单、券商条件单均不落入程序化交易定义、无需报备；一旦脚本自动发单即进入「先报告、后交易」框架（证监会《证券市场程序化交易管理规定（试行）》，2024-10-08 施行）。高频认定阈值媒体口径与正式文本存在分歧，以交易所正式细则为准，本文不采信任一数字作结论。
  • 数据：行情保持个人自用、注明来源、不对外分发；AI 稿件 / 自媒体数字只进待核实队列，字段一律 null；一手来源（交易所公告、公司定期报告）与非一手来源分级标注。
  • 提示语：白名单模板，不出现操作判断；异常波动公告不等于基本面反转信号；单日打开跌停不等于恐慌盘出清，必须由后续行情反馈判定。
  • 安全：sidecar 只读挂载、绑定 loopback、无下单与写库权限；Langflow 有未认证 RCE 历史漏洞（CVE-2025-3248），不裸奔公网；网页内容对智能体一律视为不可信输入（提示注入风险）。
  • 成本：开源省的是软件许可费，模型 API 或本地算力照付；sidecar 的 checkpoint 存储会随使用增长，1.2.18 起快照更频繁，需监控体积。
  • 反过拟合纪律：n≥30、IC>0.03、IR>0.5、样本外不劣化、一次只登记一个主假说、冻结基线 v0 永久对照、失效即退役；好经验与踩坑经验同门槛，无 precommit 的「成功经验」一律不采信。
