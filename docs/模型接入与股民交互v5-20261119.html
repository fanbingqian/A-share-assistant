二、可以用 DeepSeek 吗：可以，但四条必须照做

2.1 接入方式

DeepSeek API 使用 OpenAI 兼容格式，base_url = https://api.deepseek.com，改配置即可复用官方 SDK。LangGraph 侧通过 ChatOpenAI / init_chat_model 指定 base_url；Pydantic AI 侧有原生一等公民 DeepSeekProvider，不需要用通用兼容写法凑合。

# Pydantic AI（推荐用于 R1 强类型抽取）
from pydantic_ai import Agent
from pydantic_ai.models.openai import OpenAIChatModel, OpenAIChatModelSettings
from pydantic_ai.providers.deepseek import DeepSeekProvider

agent = Agent(
    OpenAIChatModel(MODEL_ID, provider=DeepSeekProvider(api_key=KEY)),
    output_type=Claim4,                       # 主张/证据/来源/时点 四元组
    model_settings=OpenAIChatModelSettings(thinking=False),
)

# LangGraph / LangChain 侧
from langchain_openai import ChatOpenAI
llm = ChatOpenAI(model=MODEL_ID, base_url="https://api.deepseek.com",
                 api_key=KEY, temperature=0)
模型 ID 不要硬编码：核实中不同来源对当前模型名表述不一致 —— 一方列出 deepseek-v4-flash / deepseek-v4-pro，Pydantic AI 官方页则建议 deepseek:deepseek-flash 并称 deepseek-v4-flash 为旧名；旧 ID deepseek-chat / deepseek-reasoner 已于 2026-07-24 退役。存在口径差异，以调用当日官方模型列表为准，把 MODEL_ID 写进配置项而非代码常量，升级时只改配置。
来源：DeepSeek 官方 API 文档（api-docs.deepseek.com）、Pydantic AI 官方 DeepSeek 页，2026-11-19 检索；具体版本号与别名需核实官方当日文档。

2.2 结构化输出的四个坑（直接决定 R1 能不能用）

坑后果本项目的处置
Chat Completions 只有 response_format={"type":"json_object"}，原生 json_schema 仅 Responses API 的 text.format 支持服务端不按 Schema 强约束Prompt 必须含字面词 json 并给示例；输出一律再过 Pydantic 校验，不信任服务端
模型输出无法识别为 JSON 时，API 把内容替换为空格 U+0020，而 finish_reason 仍是 stop看起来返回成功但内容是空的必须做空白 content 兜底与重试，不能只写 json.loads；网关把这类输出标为「已剔除」并在研发视图显示
V4 模型默认思考；思考时拒绝强制 tool_choice，Pydantic AI 只能发 auto，模型可能改用散文作答而不调输出工具重试预算耗尽，抽取任务失败结构化抽取一律 thinking=False；显式传 tool_choice='required' 且思考开启会在客户端抛 UserError
Responses API 无状态；不支持的参数静默忽略；previous_response_id 会让历史被静默丢弃功能失效不报错、对话丢失本项目用 Chat Completions + deepseek: 前缀；多轮历史由 LangGraph checkpointer 自己保存并每次回传，不用 Responses 的会话机制

另有两条实现细节：strict 模式需 https://api.deepseek.com/beta 且所有 object 属性必须 required、additionalProperties:false，默认 URL 上「接受但忽略」；思考请求中工具调用轮次缺 reasoning_content 会被拒，DeepSeekProvider 会补空值。这些都不需要本项目自己实现，但要在联调时确认版本已包含。

2.3 数据合规：本轮最重要的红线

《DeepSeek开放平台隐私政策》第七章第 2 款（发布 2026-11-04、生效 2026-11-11）原文：除另有书面约定外，在经安全加密技术处理和去标识化前提下，可能将通过开放平台提交的输入和输出用于开发、训练、评估及改进模型、算法、安全系统。这与消费级 chat 产品里那个可关闭的开关不是同一机制，政策未给出默认 opt-out 开关；若要求数据不进训练，须争取书面约定（企业协议 / DPA）。
允许传给模型 API禁止传给模型 API
股票代码、交易日期、已核实的价格 / 涨跌幅、信号名称、口径标签、脱敏后的复盘文字券商账户、资金量、持仓市值、完整持仓明细、身份证 / 手机号、API 密钥、他人信息、任何敏感个人信息

另外两点：① API 本身无状态、服务端不留多轮历史，这缩小了服务端累积面，但历史留存责任完全落在客户端 —— 本地 SQLite checkpoint、OTel trace、JSONL 日志都在你自己机器上，要自己管好；② 政策称境内收集的信息存储于中国境内、「目前」不会传输至境外，措辞留有余地，若将来产品对外服务需重新审阅。个人自用时，最稳妥的兜底是把敏感字段留在本地、只发脱敏结构化事实，必要时切本地模型（Ollama 等兼容端点）。

3.3 与现有 8777 系统的衔接（不推翻数据管道）

你已经有数据源了：server/sources.js 与 7 类状态缓存（market-breadth / market-style / strength-cache / phase-cache / flow-cache / cycle-cache / attribution-cache）已经覆盖行情与市场状态。MCP 在这里不是替换它们，而是三个补充用途：① 把现有 JSONL 事实账本与缓存暴露成只读 MCP server 给 sidecar 调用（自己写一次，任何兼容 Agent 都能接）；② 补现有系统没覆盖的公告原文、财报、宏观序列；③ 技能包提供「怎么分析」的流程模板。这样既不破坏零依赖主服务，又让能力可移植。

3.4 个人经验池：也不做训练

你说「训练的部分主要是个人经验池」—— 这里要纠一句：连经验池也不该微调模型。微调会带来五个与本项目根本冲突的后果：不可审计（说不清哪条经验改了什么）、无法逐条回滚或删除、无法证伪、在现有 18/30 的小样本上必然过拟合、且与前面四版定下的「人工闸门 / 冻结基线 v0 / 失效退役 / 有界回流」全部打架。

✅ 正确做法
经验池 = 可读可改可删的 JSONL 账本；用时按 patternFamily + scope + 画像 检索相关条目作为上下文给模型（检索增强），模型只负责措辞；经你审核采纳后，才以 ±2 分 / 乘数 0.8–1.25 / 不翻符号的幅度回流到评分，并冻结 v0 对照。
❌ 不做
不微调、不 LoRA、不把经验喂成权重、不让模型自己「悟」出规则。经验的价值在于可举证、可退役、可反例校正，一旦变成权重就全丢了。

国金证券 2026-04-30《大模型赋能投研之二十：从金融文本数据到投研工作流》把金融 Skills 分为信息数据类 / 工具效用类 / 投研应用类，可作技能卡分类参考；该研报为非一手转述，需核实原文。

四、界面定位纠偏与四个股民方案

先承认一个偏差：v4 交付的 B 三栏工作台 / C 复盘时间线，右栏放的是证据链、并列假说、冲突标签、schema 校验 —— 那是研发观察视角，不是股民该看的东西。本版按你的要求重新定位：股民模式是默认且最终形态，推导过程只在研发期以开关形式保留。

4.1 双层呈现：不是两套 UI

同一份数据、同一渲染层，只切一个 detailLevel = retail | dev。股民模式：大字号、结论与提示优先、不出现「假说 / 证伪 / IC / schema / 幂等」等术语、红涨绿跌、只展示有实质变化的维度（不写「暂无变化」占位）、点一下才看「为什么提醒我」。研发模式：展开完整推导链、来源时点、样本数与反例数、网关校验与被剔除输出、参数滑块（改动不写生产）。发布时只需隐藏研发入口，推导视图整体下线，避免两套界面长期分叉。

4.2 四个面向股民的方案

方案形态最适合弱点
① 今日三件事三张大卡：大盘一句话 / 我的股池提醒 / 今天要做盘前盘后 3 分钟扫一眼，小白零负担信息密度低，看不了全池
② 股池看板推荐主屏券商自选股式表格，多一列「提醒」与「为什么提醒我」学习成本最低，股民最熟悉；可排序筛选、批量管理需要 ≥1280px 宽屏
③ 复盘卡流日期轴 + 每日卡片 + 常驻口语录入 +「我的经验本」长期累积感，把经验变成看得见的成长记录不适合做实时监控首屏
④ 问一句对话入口 + 三个快捷问题，回答只用已核实事实拼装最直觉、对小白最友好最需防幻觉：答案必须由确定性结果拼装，模型只做措辞；无出处的问题直接拒答

推荐组合不是四选一：② 作日常主屏 + ① 作盘前 / 盘后首屏 + ③ 作复盘子页 + ④ 作可选入口；研发模式作为全局开关覆盖在任一方案之上。四个方案已在可交互原型中实现并可切换。

4.3 研发期保留的推导链（六步，逐环节可点开）

步展示内容你在研发期要观察什么
1 事实输入A/B/C 来源分级、来源时点、取数日数字是不是从行情数据读的（不能从股池列表附带字段读，那可能是振幅而非涨跌幅）
2 确定性计算gap / intraday 公式、四象限、Flag 规则 ID、样本与反例数口径是否一致；形态与当日涨跌是否分开存
3 智能体输出R1 四元组 JSON、R2 假说卡、R3 冲突标签、R4 提示语、thinking=False 标记模型有没有补数字、有没有写「因为 X 所以涨」
4 确定性网关schema / 出处 / 幂等校验结果，被剔除的输出及原因AI 稿件的 PE 等数字是否被置 null、空白 JSON 返回是否触发重试
5 人工闸门待审队列状态、interrupt/resume、采纳边界有没有绕过人工审核直接写 rules.json
6 回填校准T+1/5/20 回填、假警报率、反例计数风险回避价值与假警报率是否并列看

研发面板还带三个参数滑块（提示阈值 / 样本门槛 n / 每日 Flag 上限），只改本地预览、不写生产配置。等口径稳定后，股民模式只保留「为什么提醒我」这一层事实说明即可。

4.4 PC 使用习惯与内容纪律

  • ≥1440px 宽屏为主；窄屏时研发面板自动移到下方，不横向滚动；字号比 v4 原型放大一档。
  • / 聚焦录入 / 提问，Esc 关闭研发视图；审核用就地二次确认，不弹模态。
  • 红涨绿跌（A 股习惯）；提醒色与涨跌色分开，避免误读为买卖信号；零 CDN、离线可用。
  • 不做每日涨跌方向预测，只给「观察重点 + 风险/机会框架」；不写「无变化」占位；不推荐超出认知范围的标的；不用绝对语言。
  • 常见误导信号要在提示里体现：利好消息发布 ≠ 股价必涨、单日跌幅大 ≠ 趋势反转、跌停打开 ≠ 恐慌盘出清 —— 这正是通化金马案例给出的教训。
