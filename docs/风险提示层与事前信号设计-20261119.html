风险提示层（Flag）与事前信号设计

GlobalMarketMonitor 设计文档 v2 · 2026-11-19（盘后）｜以通化金马（000766）医保目录事件为原型案例｜性质：架构设计 + 事实对账，不含投资建议

结论先行：你这句话改了架构

你澄清「知识库不是为了 100% 判断，而是提醒 / 风险提示；风险不是绝对判定；需要真实市场数据反馈和分析」——这正好是上一版框架的缺口。上一版我把因素分成 Gate（剔除）/ Score（评分）/ Explain（解释） 三类，并把「利好出货」放进 Explain。这偏保守了：Explain 只解释、不统计、不验证，无法承担你要的「选股重点 + 数据反馈」。因此需要新增第四类 Flag（风险提示）。

1 · 这条案例不能按「五个原因」入库

「利好兑现 / 医保降价 / 三季报转亏 / 板块退潮 / 杠杆踩踏」是跌完之后组织出的叙事，事后永远成立、不可证伪、反例极多。写进选股会退化成「永远看空」。

2 · 能入库的是「买入前可算」的信号

公告前抢跑涨停、支付标准未公布、协议期 2027 才执行、同标的 6 个月内重复模式、估值业绩背离、资金结构分歧——这些在你下单之前就存在，且每条都能被真实行情回填验证。

3 · Flag 只提示，不否决

三级「提示 / 警示 / 强警示」，默认不改分、不剔除、不自动下单；每条必须同时显示历史反例数。要从 Flag 晋升到 Score，仍须过上一版的影子验证 + 人工闸门。

4 · 反馈指标不是「预测准不准」

而是「触发后回避了多少回撤」与「误报率（触发后仍上涨）」并列统计。没有反例计数的风险提示，和事后归因一样不可信。

最值钱的一条信号不是「医保利好会跌」：同一标的在 2026-06-25 药品注册证公告后，已经演过一次「公告前抢跑 → 公告后连续跌停」，并在 06-30 发过异常波动公告。四个月内同一剧本第二次上演——这是可事前计算、可计数、可证伪的重复模式，比任何因果解释都可靠。来源：深交所公告列表 2026-06-25 / 2026-06-30，见文末来源 [2]

三处修正带来的教训，比案例本身更重要：
① 日期口径必须先对齐：如果经验库把 11-18 当作「今天」，precommit 与 outcome 会错位一天，反馈台账全错。
② 你复盘中列的「跌停打开 + 放量换手」这个真信号，11-19 其实已经出现（盘中触及跌停未封、换手由 2.08% 升至 4.98%、成交由 2.43 亿升至 5.36 亿），但当日仍收跌 7.98%。按日度简报纪律，单日「打开跌停」不等于恐慌盘出清，需多日确认——若系统把这条写成买入信号，11-19 就会误判。这正是「提示必须由真实行情反馈、而不是由叙事判定」的现成例子。
③ 事件落地后公司层面没有新增利空（异动公告已确认）。所以「五个原因」里多数是事前已公开的静态背景，不是事件后的新信息。

Flag 的六条硬规则

  1. 三级而非二元：提示 / 警示 / 强警示。避免「有风险 = 有问题」的绝对判定，这是你明确要求保留的空间。
  2. 默认不改分、不剔除、不自动下单：只做显示与记账。要影响评分，必须走上一版的五级晋升阶梯（事前登记 → 单一主假说 → 影子验证 → 人工采纳 → 失效检测）。
  3. 必须带反例计数：同一信号组合历史上「触发后 T+5 仍上涨」的次数，与命中次数并列展示。没有反例计数的 Flag 不允许升级为强警示。
  4. 必须带来源与时点：每条信号指向公告编号 / 行情日期 / 数据源；来自 AI 稿件的字段一律标「需核实原文」，不得写入事实账本。
  5. 必须可关闭：适配器与 Flag 层都能一键关掉，关闭后主服务照常运行。
  6. 提示语不得含操作指令：只陈述可验证事实与历史统计，不写「别买」「不接飞刀」「等打开跌停」这类判断。

四、真实市场数据反馈：提示有效性台账

你说的「需要真实的市场数据来进行反馈和分析」，落到系统里就是这张台账。它可以复用项目已有的 journal.js 能力：barOf(code, date) 取日线、benchRet(bucket, date) 取同市值层基准，无需引入新依赖。

回填字段计算口径用途
t1 / t5 / t20触发日后 1 / 5 / 20 个交易日收盘相对触发日收盘的涨跌幅衡量提示后短期与中期走势
maxDrawdown20d触发后 20 个交易日内，相对触发日收盘的最大回撤核心指标：这条提示帮用户「看见」了多大风险
excess同期收益 - 同市值层基准收益（基准缺失则记 null 并从统计中剔除）剔除大盘整体影响，沿用上一版的口径修正
verdictuseful / false_alarm / inconclusive，由确定性阈值判定，不由 LLM 判定形成样本，供晋升阶梯使用

两个必须并列看的统计指标

  • 风险回避价值：被标为警示的样本，其后 20 日平均最大回撤 vs 同期全池平均最大回撤。
  • 假警报率：触发后 T+5 仍跑赢基准的比例。这个数字必须和上一个一起显示，否则系统会越来越保守，最后对所有票都报警，等于没有提示。
防止重蹈上一版的覆辙：上一版已发现 journal.js 在 18 条样本上按 7 个维度切分生成经验、无多重比较校正。Flag 台账必须吸取同一教训：一次只登记一个主信号组合，探索性切分只标「待复现」；样本 n ≥ 30 且样本外不劣化前，不得把任何 Flag 晋升为评分规则。

反例库：data/journal/counterexamples.jsonl

专门记录「同样信号组合触发、但后续上涨或跑赢基准」的样本。它的作用是给每条提示配一个「这句话也可能错」的可见计数。用户要的不是 100% 判断，这个库就是该定位的技术实现——没有反例库的经验库，本质上只是确认偏误的放大器。

你这次的输入恰好是三类信息的混合体，正好用来定来源分级规则。

B 用户亲历「我看到纳入医保的消息后买了，之后连续跌停」可写入，标 source=user_note作为行为账本与复盘入口，不作为市场事实

由此得到一条系统级规则：智能体输出永远是线索，不是事实。它只能做三件事——把用户的口语经历归类成信号标签、生成待验证假说、把确定性结果翻译成人话；所有数字必须来自 L0 事实账本。这条规则上一版已定，本案例是它第一次遇到真实压力测试。

八、合规与风险边界

  • 系统只输出风险提示、事实与历史统计，不输出买卖 / 价位 / 仓位判断；不自动下达委托单，则不落入程序化交易定义、无需报备（依据：证监会《证券市场程序化交易管理规定（试行）》相关口径，2024-10-08 施行；具体适用以证监会及交易所正式细则为准，本文不构成法律意见）。
  • 个股「异常波动」「增持计划」等公告信息属公开披露内容，界面须保留免责声明，不做收益承诺、不对外提供投顾服务。
  • 行情数据保持个人自用、注明来源与时点、不对外分发；媒体与 AI 稿件属非一手来源，需标「需核实原文」，不与交易所公告同等处理。
  • A 股语境红涨绿跌；风险提示必须同时显示样本数、反例数与「尚未验证」状态。
