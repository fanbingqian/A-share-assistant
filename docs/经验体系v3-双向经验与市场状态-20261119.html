先给结论

  1. 不用另起炉灶。你要的「大盘状态 / 板块轮动 / 涨跌原因」数据，系统里已有七类缓存；缺的是把它们组织成「可证伪的解释 + 双向经验 + 冲突并列」的那一层，以及界面上放证据的位置。
  2. 「冲突需要智能体」只对一半。冲突里的事实与口径冲突靠确定性重算裁定，解释冲突根本不该被裁决。LLM 的合法职责是发现、抽取、归类、生成证伪条件；最危险的行为恰恰是它默认会做的「折中合成」。
  3. 形态是计算，原因是假说，两者永不混存。四象限由开/收/前收三个数算出来，写进事实账本；「背后逻辑」只做成带证伪条件的假说卡，每天最多登记一个主假说。
  4. 交互不是三选一。推荐「现有三栏工作台补右栏」作骨架 + 「今日结论卡」作首屏 + 「复盘时间线」作子页 + 复用已有桌面通知作提醒通道。
  5. 参考程序只借鉴架构，不搬代码。检索到的开源项目里，没有单一项目同时做好状态识别、轮动分析与复盘知识库；且多数是 Python / GPL / AGPL，与零依赖 Node 主服务冲突。

二、双向经验账本：踩坑与好经验，都走同一道闸门

2.1 三个必须补的维度

维度取值为什么必须有
polaritypitfall 踩坑 / win 好经验两类都要存。只存踩坑会让系统越来越保守；只存好经验会放大确认偏误。
scopemarket 大盘 / sector 板块 / stock 个股 / self 自身行为「高开低走」是大盘层，「医保准入但支付标准未公布」是个股层，「我又追高了」是自身行为层，混在一起无法统计。
patternFamily + variant族群 + 变体两级回应你说的「每次出现的问题可能都不一样」：新情况生成变体子条目，挂到同一族群下，不覆盖原条目、不无限并列。例：event-sellnews 族群下挂「新药获批」「医保准入」「订单公告」等变体。

2.2 个性化画像：显式声明 + 行为反推，冲突时以行为为准

同一个提示对不同的人价值不同。系统要有 profile.json，但不能靠 LLM 猜画像：一半字段由用户显式填写，另一半从 trades.jsonl（v1 已提出、尚未建立）确定性计算，两者不一致时以行为为准并给提示。

显式声明（用户填）

  • 自述风格：隔夜短线 / 波段 / 中长线
  • 单票仓位上限、可接受最大回撤
  • 是否做 T、是否参与涨停/打板
  • 偏好的买点类型：追涨 / 回踩 / 突破
  • 常用信息来源：公告 / 研报 / 自媒体 / 他人推荐

行为反推（确定性计算）

  • 实际持仓周期分布（中位数、P90）
  • 买入时相对 20 日高低点的位置分位
  • 仓位集中度、单日换手频率
  • 计划偏离度：实际操作 vs precommit
  • 处置效应：盈利单与亏损单持有天数之差
  • 复盘覆盖率：有复盘的交易日占比

画像只影响「提示怎么显示、显示给谁」，不直接改评分。例：「高开低走 + 缩量」对隔夜短线画像标「强警示」，对中长线画像标「仅供参考」，但两者背后的事实与反例计数完全相同。这样个性化不会变成给不同人编不同结论。

2.4 同一套闸门，两个方向

闸门踩坑经验好经验（更容易被放过的地方）
事前登记写下「什么现象算我错」同样必须写。成功最容易事后编理由，没有 precommit 的「好经验」一律不采信。
影子验证不改分，只记触发与后续 T+1/T+5/T+20同左；且必须统计「同样信号触发但没赚到」的样本。
样本门槛n≥30、样本外不劣化、单一主假说同左，不放宽。
人工采纳审核后才可回流同左，不允许「看起来很合理」直接升为规则。
有界回流±2 分 / 乘数 0.8–1.25 / 不翻符号同左，且冻结基线 v0 永久对照。
失效退役连续两期样本外劣化 → retired同左。市场状态变了，好经验也会过期。

三、两市四象限：形态是计算，原因是假说

3.1 可计算定义（写死，不允许 LLM 改写）

gap      = open / prevClose - 1
intraday = close / open - 1
dayChange = close / prevClose - 1
quadrant = (gap >= 0 ? "高开" : "低开") + (intraday >= 0 ? "高走" : "低走")

上证（sh000001）与深证成指（sz399001）各自独立标注；两市象限不一致时记 divergence: true，这本身就是一条值得入库的结构信号。

必须区分 intraday 与 dayChange。「高开低走」不等于「指数下跌」。以 2026-11-18 为例：前收 3584.58、开 3596.55、收 3587.83，按定义是高开低走，但当日 dayChange 为 +0.09% 仍是收涨（来源：westock-data sh000001 日 K，取数 2026-11-19）。若把两者混成一个字段，系统会把「形态」误写成「涨跌结论」。

3.2 「含金量」六维：全部映射到已有缓存，不新建数据管道

观察维度直接取用的字段指向高走 / 指向低走
市场广度market-breadth.json: up / down / agg上涨家数占优、多板块普涨 → 高走；涨少跌多、仅权重独拉 → 低走
量能位置market-style.json: ratio20 / z20 / percentile / state温和放量 → 高走；地量、缩量高开 → 承接不足
板块位置phase-cache.json: stage / ex5 / ex20启动 / 加速且扩散 → 高走；高位 / 退潮 → 兑现压力
相对强弱strength-cache.json: leaders / laggards / crowdCross主线清晰且多板块同步 → 高走；单一板块独涨 → 脆弱
资金主体flow-cache.json: actors / tilt / margin增量入场 → 高走；存量博弈、杠杆退潮 → 低走
避险形态riskoff-cache.json: form / direction无避险形态 → 中性；L1 板块内轮动 / L2 风格避险 → 结构分化

方法论依据：项目内 references/market-state.md（广度恶化是前置信号、指数涨不等于健康）、references/macro-transmission.md（传导链必须经中间变量）、references/abnormal-detection.md（跳空四类归因、位置决定含义）。字段来源：项目内缓存文件，2026-11-19 核验。

阈值不要照抄外部统计。检索到的「高开低走占 19.59%、低开高走占 29.81%」「微高开走低约 54%」等数字来自媒体转述与民间回测，非一手来源、需核实原文，口径（指数 vs 全 A、样本区间、形态定义）均不明确。系统应改用自身历史开盘分布做分位，不预置普适阈值。

3.3 板块轮动与涨跌原因：只做「线索 + 假说」，不做结论

  • 轮动阶段直接复用 phase-cache.json 已定义的五阶段，不新造分类。方法论 references/sector-comparison.md 明确要求按「逻辑 / 位置 / 催化 / 资金 / 拥挤度」横向比较，并写有硬约束：板块轮动是结果不是预测，别用后视镜推断下一个是谁。
  • 背后原因按 references/abnormal-detection.md 的四类驱动排查：事件 / 板块 / 技术 / 资金；每条只登记为线索，附来源时点。宏观层若涉政策或利率，须写出 A → B → C 完整传导链，不允许「所有板块都受益」式泛化。
  • 「利好出货 vs 提前布局」这类判断事后永远能自圆其说。唯一能变成经验的方式仍是 v1 定的 precommit：事前写预判与证伪条件，事后只做对照。cycle-cache.json 的 sellNewsRate 可直接作为该族群的支持/反例计数器。

4.2 四类冲突与处理流水线

类型典型场景谁裁定处理方式
① 事实 / 口径冲突形态标签不一致；单市场 vs 两市成交额；复权 / 时点差异确定性重算（代码）对齐元数据 → 按来源等级采信一手行情 → 另一条标 conflict 保留，不删除。LLM 不参与。
② 解释冲突「利好兑现」vs「板块退潮」vs「杠杆踩踏」不裁定并列假说，各自带机制链、证伪条件、supportN / contradictN；后续样本自然调权。禁止合成。

④ 价值冲突风险 Flag 与自己的买入理由相反用户界面左右并列展示，系统不改分、不剔除、不给操作建议。

4.4 智能体在这里的确切位置（回答「是否需要智能体」）

需要，但职责必须收窄。冲突的「发现」与「归类」确实是 LLM 的强项——它能从两段不同措辞里看出在说同一件事、或主张互斥；但「判定谁对」不是。

允许（L2 / L3）

  • 从叙述中抽取「主张—证据—来源—时点」四元组
  • 检测语义互斥、把冲突归入上述四类
  • 为假说生成可观测信号与证伪条件
  • 把确定性结果翻译成人话，标注来源等级
  • 把口语复盘归类到既有 patternFamily 标签

禁止（写进系统提示词与输出 schema 校验）

  • 判定哪条解释正确、给置信度当成裁决
  • 把多条冲突解释折中合成一条（最高危）
  • 按文字流畅度、篇幅、出现次数投票
  • 改写或补全任何行情、财务数字
  • 把 C 级来源的数字写进事实账本（一律置 null）
  • 给出买卖、仓位、价位判断

实现方式沿用前两版结论：不引入 Agent 框架，用 Node 内置 fetch 写薄适配器调 OpenAI-compatible 接口，前置确定性网关（事实账本核对 / schema 校验 / 幂等去重 / 无出处即剔除），后置待审队列与人工闸门，可一键关闭。第二阶段若确需多角色复盘，再考虑独立 Python sidecar 跑 LangGraph，且只暴露 /proposal，不碰 8777 主服务。

6.1 从电脑使用习惯出发的硬约束

八、合规、边界与来源

  • 只要程序不自动下达委托单，回测、信号、人工下单、券商条件单均不落入程序化交易定义；一旦脚本自动发单即进入「先报告、后交易」框架（证监会《管理规定（试行）》，2024-10-08 施行）。高频认定阈值以交易所正式细则为准，本文不采信任何媒体口径数字作结论。
  • 行情数据保持个人自用、注明来源与取数时点、不对外分发；外部 AI 稿件 / 自媒体的数字一律置 null，只进待核实线索队列。
  • 来源分级：A 交易所公告 / 一手行情（可直接入事实账本）｜B 用户亲历（只进行为账本，标 user_note）｜C 其他智能体 / 自媒体稿件（只进待核实队列）。
  • 系统输出永远是「提醒 + 证据 + 反例」，不产出买卖、价位、仓位判断；风险提示不等于风险判定，须由真实行情 T+1/T+5/T+20 反馈并同时统计假警报率。
