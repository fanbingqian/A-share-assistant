全球市场监测系统 · 架构重研究与板块完善方案

审计日期：2026-11-22 20:40 · 基于真实代码、真实缓存与实测接口 · 本文只做分析与方案，未改动业务代码
一句话结论：五模块的「外壳和本地数据链路」基本搭好了，但你的需求里真正有价值的三件事——事件历史统计与主动提醒、9 点预测快照与自动复盘、三类选股规则——目前都还没有真正跑起来。阻塞原因不是智能体不行，而是数据底座缺生产者、缺定时调度、缺统计引擎、缺前端订阅。智能体对话链路今天已修复并验证走官方 Hermes。

知识库 · 智能问答部分运行基于知识库回答。纯 LLM、无降级，断网即失败。

日程 · 事件影响统计不能运行只有「智能体解读」按钮，返回一段 LLM 文字。没有近 2 年事件库，没有历史涨跌统计。calendar.js 不读任何行情/K 线，无法算 T+1/T+3/T+5 胜率与 AR/CAR。
每日行情 · 实时监控部分运行量能、风格、板块强度、涨停结构、观察池评分都能显示。依赖缓存；market-style.json 停在 11-20，外网刷新失败时只能回退旧数据。technical-cache.json 显示 barsOk:0 / barsFail:14。
每日行情 · 9 点预测快照不能运行只有点「智能体解读」时才临时生成一次。没有 9 点定时任务，没有独立快照文件。文本只进 predictions.jsonl，目前仅 1 条且未复盘。
每日行情 · 复盘部分运行predictions.js 的 record / judge / review 代码本身完整，能用本地实际值判命中。无定时、无报告模板、无「今日复盘」生成；predictions-actual.json 只有 1 天，样本不足；复盘后无自动知识入库。
选股① 热度 / 独立行情牛股部分运行现有的是「涨停板热度」：连板数 + 封单占比 + 首封时间 − 炸板次数。不是你要的独立行情牛股。缺少个股 vs 行业 / 大盘的超额独立性字段。
选股② 趋势股不能运行pickResilient() 只读 ma5-screen.json 做 breaks≤1 过滤。文件停在 11-21 且全项目无生成器；字段只有 d/c/ma5/below，没有 high，无法判断「期间创新高」；也没有「连续 3 日不破 MA5」专门判定。
选股③ 强势反弹股不能运行当前第三类叫「防守型个股 / ETF」。与需求完全不同。无超跌判定、无长下影判定；data/defensive-cache.json 根本不存在，返回空数组。
前端提醒卡片 / 弹框部分运行事件卡片内嵌「智能体解读」结果；toast 轻提示。服务端推了 v2-volume / v2-calendar SSE，前端未订阅，所以没有「事件出现自动弹框」。
最关键的四个「看着有、其实没有」： ① ma5-screen.json 没有生产者，是死数据；② defensive-cache.json 不存在，第三类选股恒空；③ forecast 没有定时器，只有点击触发；④ 事件模块没有历史统计引擎，LLM 解读不等于经验统计。

3.1 日程与事件：从「日历」升级为「事件研究 + 主动提醒」

数据结构（新增 data/events/registry.jsonl）

字段说明

历史统计引擎（新增 server/eventstudy.js）

每个事件发生后自动计算并落盘 data/events/stats.json：

  • 窗口收益：T−5 / T−1 / T0 / T+1 / T+3 / T+5 / T+10 的相关板块指数与个股收益。
  • 超额收益：以沪深 300 为基准，计算 AR 与累计 CAR；方法参考 lixia1118/Event-study-calculator 的市场模型与统计检验。
  • 经验概率：按「事件类型 × 板块 × 重要级别」分组，给出上涨比例、样本数 n、平均涨幅、最好/最差、胜率。n<5 必须标「样本不足，仅供参考」。
  • 走势形态：T+1 高开低走 / 低开高走 / 连续放量等归类，供智能体写卡片时引用。

卡片固定三段：① 什么事情（事件、时间、信源、是否已确认）→ ② 对这件事的分析（历史 n 次、上涨概率、平均走势、相似事件）→ ③ 观察建议（只写「若…则…」的验证条件与证伪点，不写买卖指令）。

实现要点：前端 v2.js 需要订阅 v2-calendar SSE；后端在事件入库时调用 eventImpact() 并把结果作为卡片内容推送，而不是只在用户点击时生成。

任务目标形态必须新增

建议采用的「全面复盘报告模板」（12 节）

这是综合 GitHub 多个项目后，适配本系统数据口径的版本：

#章节内容
1摘要与一句话定性指数、成交、宽度、情绪各一句；红涨绿跌；数据日与生成时间。
2指数与量能沪深创科创收盘、涨跌幅、成交额、较 20 日均量、封闭/放量方向。

5资金结构主力净流入、分档；无数据就写「待补充」，禁止估算冒充实测。
6主线延续与五日对照前日强势方向的延续 / 分化 / 退潮，五日序列。

复盘后如何判断「有用的」纳入知识库

  1. 程序生成结构化候选：事实（已发生）、经验（可复制规律）、待验证（有证伪条件）。
  2. 过 knowledge.js 现有价值门控：闲聊 / 纯情绪 / 无信息量直接丢弃。
  3. 智能体给每条候选打标签、关联板块与个股、写明适用市场状态。
  4. 与已有笔记做去重 / 冲突检测；命中冲突进入 pending-merge 裁决，不自动覆盖。
  5. 默认只写 extracted:false 候选，用户确认后才 confirmNode 进正式图谱。

3.3 选股三类：把口径写死成可计算规则

类型精确定义（建议）需要新增的数据 / 文件
① 热度 / 独立行情牛股独立性：近 5 日个股收益 − 所属行业收益 − 沪深 300 收益 > 阈值；且行业本身未同步大涨。
热度：换手率分位 + 连板高度 + 首封时间 + 封单占比 − 炸板次数。
两者同时满足才入选。		个股行业归属、行业指数日收益、个股换手率、涨停明细（已有 limitup-cache 部分字段）。
② 趋势股规则 A：最近 3 个连续交易日 close ≥ MA5。
规则 B：最近 5 个交易日中 close < MA5 不超过 1 天，且窗口内 max(high) > 前 20 日 max(high)（创新高）。
满足 A 或 B，并排除 ST / 停牌。		必须生成带 high / low / volume 的日线快照 data/trend-screen.json；新增 server/screener.js 生成器。
③ 强势反弹股超跌（满足其一）：20 日收益 ≤ −15%；RSI(14) ≤ 30；收盘价低于 MA20 达 10% 以上。
长下影：lowerShadow = min(open,close) − low，要求 ≥ 2×ATR(14) 且 ≥ 1.5% 股价；且 close 位于当日振幅上 40%（收在下影线之上）。
有分钟数据时，「尾盘」限定为 14:30 后；无分钟数据时用日线收盘位置作代理并显式标注。		日线 OHLC + ATR + RSI；新增 data/rebound-screen.json。「超跌」阈值需先用 2 年历史回测校准，不能直接写死。
当前 technical.js 里已有 holdMa5NewHigh / resilience 等因子代码，但算不出来：technical-cache.json 显示 14 只标的 barsOk:0, barsFail:14，全部 calc:null，错误是 socket hang up。所以先把 K 线源修复或换备用源，是三类选股的前置条件。
