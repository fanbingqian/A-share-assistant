智能体感知模块方案：技能 + MCP 解耦

基于 AI-Hel2 的 agent↔知识库模式调研 + 本机 Hermes 实测 · 2026-11-22 · 核心原则：不动约束层，只加感知能力

一句话结论：AI-Hel2 的做法是「知识不进 system prompt，而是注册成工具让模型按需调用」。你的 Hermes 内核完全支持这套模式（原生 -s/--skills、mcp_servers、--max-turns），且 skills/memory/terminal/file 工具集都已启用。可以做到：日程事件、每日行情、板块数据由智能体「主动感知」，而不是把数据硬塞进提示词，也不改任何安全约束。

一、AI-Hel2 如何处理智能体与知识库的关系

我逐行读了 AI-Hel2 的知识库与 agent 层，它的关系设计非常清晰——三层解耦：

1. 知识库独立成 HTTP 服务，不做成提示词

Nexus 知识引擎跑在 127.0.0.1:18643，对外提供 /nexus/search、/nexus/entity/:id、/nexus/paths、/nexus/neighbors/:id、/nexus/map 五个端点。

源码：src-tauri/src/services/nexus_api.rs

2. 工具定义只有一份，同时供两条路使用

nexus_tools::nexus_tool_definitions() 一个函数生成 5 个 OpenAI function-calling JSON Schema，被两个地方同时引用：

  • OpenAI-compatible 直连：build_request() 里 req["tools"] = nexus_tool_definitions()，tool_choice: auto；
  • MCP 端点：nexus_mcp.rs 的 tools/list 直接返回同一份定义，外部智能体也能通过标准 MCP 协议访问。

源码：src-tauri/src/services/agents/nexus_tools.rs、nexus_mcp.rs、openai_compatible.rs

3. 工具结果回灌，形成多轮循环

模型返回 finish_reason: tool_calls → 执行工具 → 以 role: tool 把结果塞回 messages → 再次请求模型，循环直到 stop。整个过程通过 ChatEvent::ToolProgress 在 UI 展示进度。

源码：openai_compatible.rs 第 382–440 行的 loop

关键洞察：AI-Hel2 里 agent 与知识库是「调用者 ↔ 被调服务」关系，不是「提示词塞满数据」关系。这正是你想要的方向——智能体保持原生状态，只是多了几个可调用的能力。

三、方案设计：三层感知架构

第 1 层 · 数据快照（Node 侧，Windows）

在 Node 8777 服务里增加「感知快照导出」：每次调用 /api/v2/chat（或定时）把五个模块的关键数据写成一份精简 JSON 到共享目录：

data/agent-perception/
  ├── calendar.json      # 日程与事件：名称/日期/等级/相关板块
  ├── daily-market.json  # 每日行情：量能/涨停结构/领涨板块/风格结论
  ├── portfolio.json     # 我的股池
  ├── knowledge.json     # 知识库摘要
  └── index.json         # 快照时点 + 各文件说明

这是「程序模块内容」的落地形态：不带任何纪律文字，只有事实数据，且由程序计算、可溯源。

第 2 层 · 技能（Hermes 侧，WSL）

在 ~/.hermes/skills/market-modules/SKILL.md 建一个自定义技能，内容不是约束，而是「能力说明」：

---
name: market-modules
description: 读取本地 A 股监测系统的日程事件、每日行情、板块与股池快照。
  当用户问"近期事件/板块/量能/股池"时使用。
---
# 模块感知

快照目录：/mnt/d/WorkBuddy/projects/GlobalMarketMonitor/data/agent-perception/

- 日程事件 → calendar.json（名称/日期/等级/相关板块）
- 每日行情 → daily-market.json（量能/涨停结构/领涨板块）
- 股池 → portfolio.json

用 file 工具读取；回答时标注快照时间。快照里没有的不编造。

桥接层 hermes_bridge.py 的 CLI 参数加一项 -s market-modules 即可预加载。不改 BASE_SYSTEM、不改 SOUL.md、不改 GUARDRAIL。

第 3 层 · MCP（可选进阶，标准协议）

若要做得像 AI-Hel2 那样「一处定义、两处可用」，可在 ~/.hermes/config.yaml 注册一个 MCP server：

mcp_servers:
  market-modules:
    command: "/mnt/d/WorkBuddy/projects/GlobalMarketMonitor/hermes-bridge/market_mcp_server.py"
    timeout: 30

该脚本实现 MCP 的 tools/list 与 tools/call，暴露以下工具（与 AI-Hel2 的 5 个 nexus 工具同一范式）：

工具名作用数据源
calendar_upcoming查未来 N 天日程事件calendar.json
daily_market查量能/涨停结构/风格结论daily-market.json
sector_monitor查持续流入/长增长板块daily-market.json
portfolio_view查我的股池portfolio.json
snapshot_time查快照时点（防用旧数据）index.json
为什么这样不破坏智能体状态：技能和 MCP 是「加能力」，不是「加约束」。Hermes 的 SOUL.md、BASE_SYSTEM、L2 拦截、GUARDRAIL 全部原样保留；智能体照样有记忆、人格、技能自进化。它只是多了几个可读的数据源，跟挂 autocad-mcp 是同一类操作。

四、与当前「塞 prompt」方案的对比

维度当前（快照塞 system prompt）本方案（技能 + MCP 感知）
数据位置每次请求拼进 system 文本共享文件，工具按需读取
prompt 体积随模块增加持续膨胀恒定，只放能力说明
智能体主动性被动接收，塞什么看什么主动判断何时调用哪个工具
约束层数据混在纪律里数据与约束分离，互不干扰
可溯源依赖模型复述工具返回带快照时点，天然可查
降级通道也能看到（Node 注入）降级时自动退回快照注入，保证可用

五、落地顺序（每步可独立验证）

1
Node 侧快照导出：新增 server/perception.js，写五类 JSON 到 data/agent-perception/。验证：文件生成、字段正确、WSL 可读。
2
创建 market-modules 技能：写 ~/.hermes/skills/market-modules/SKILL.md。验证：hermes skills list 能看到。
3
桥接加载技能：hermes_bridge.py 加 -s market-modules，重启 systemd。验证：官方对话问「近期日程」能报出事件，且 backend=hermes-official。
4
（可选）注册 MCP server：写 market_mcp_server.py 并注册到 config.yaml。验证：hermes mcp list 显示 enabled，工具可调用。
5
兜底保持：降级通道继续走现有快照注入，确保 WSL 未启动时对话不降级体验。

六、红线

  • 不动 BASE_SYSTEM、SOUL.md、GUARDRAIL、L2 买卖词拦截——本方案只加感知，不加约束。
  • 快照只含程序计算的事实数据，不写任何判断结论或操作建议。
  • 工具返回必须带快照时点；数据过期时明确标注，不静默使用旧数据。
  • WSL 未启动时自动降级到现有 prompt 注入，不影响对话可用性。

本方案基于 2026-11-22 实测：AI-Hel2 源码逐行核对 + 本机 Hermes CLI 能力验证 + WSL/Windows 网络连通性测试。当前为设计稿，尚未改动任何代码。
