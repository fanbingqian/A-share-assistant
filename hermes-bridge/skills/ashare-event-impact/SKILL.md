# A 股新闻事件影响解读（ashare-event-impact）

## 定位：把「指标复述」改成「事件解释」

系统里已有一套确定性数据：新闻抓取、消息面评分、板块近似映射、关联标的清单、事件历史统计。
早期解读把这些数字逐条塞进提示词并要求「逐字引用、逐个点名」，结果模型变成指标复述机，
读完仍不知道**发生了什么、为什么会影响市场、历史上这种事出现过什么**。

本技能规定解读的主线：

```
事件解释 → 作用机制 → 二级市场影响判断 → 历史同类情形 → 证伪条件 → 精简观察
```

**历史部分必须由程序统计提供，智能体不得编。** 数据来自 `event-study.json`
（近 2 年日历事件 × 可交易 ETF 代理，T+1/T+3/T+5 相对上证的超额与胜率）。

## 何时使用

- 用户问「这条新闻到底说了什么 / 对 A 股有什么影响 / 该怎么理解」
- 用户问「历史上遇到这种情况市场怎么走 / 以前发生过吗」
- 用户嫌解读「全是数字、没有判断」「看不出重点」
- 前端「新闻快讯 → 智能体解读这条 / 解读今日新闻」走的同一套方法论（后端 `news-flash.js` v3 已落地）

不要用于：

- 判断新闻值不值得看、去重、分级 → 用 `ashare-news-triage`
- 单纯读行情 / 选股 / 日程快照 → 用 `market-modules`
- 查实时行情、抓新源、写日历、改评分 → 这些都不属于解读技能

## 方法论

### 1. 事件解释（不是标题复述）

- 说清**谁、做了什么、何时、金额 / 数量 / 日期**，只写原文明确写出的内容。
- 判定事件性质：新发生 / 已发生的转述 / 官方发布 / 匿名信源 / 公司层面 / 行业或宏观层面。
- 公司公告（回购、增减持、停复牌）主要是**公司层面信号**，不要硬放大成板块行情。
- 英文新闻以英文原文为事实依据，中文译文只辅助理解，不得据译文扩写。

### 2. 作用机制（回答「为什么会影响」）

写 1–2 条「事件 → 中间变量 → 二级市场」的传导链，并列出传导成立所需的前提。
例如：LPR 下调 → 融资成本下降 → 地产与券商估值修复（前提：信贷需求真实回暖）。
`event-study.json` 的 `MECHANISM` 是程序内置的公开机制说明，可引用，但**它不是历史案例**。

### 3. 二级市场影响判断（必须有明确结论）

从 **偏正面 / 偏承压 / 中性且分化 / 暂难判断** 四选一，写清：

- 判断依据来自新闻原文还是程序快照；
- 传导路径、受益侧与承压侧各是谁（不得所有板块都写成受益）；
- 影响的时间尺度与一阶 / 二阶差异；
- 失效条件（出现什么信号说明判断不成立）。

必须标注「判断」。**不是涨跌必然性预测，不是点位预测，不是买卖指令。**

### 4. 历史同类情形（只引用统计，不编故事）

- 先说明事件归类与统计口径（同类事件 / 相关板块代理，两者不同）。
- 逐字引用：样本数、事件次数、事件前 T-5、事件后 T+1/T+3/T+5、相对上证超额、上涨概率、超额为正比例、涨跌分布、分板块 ETF 代理明细。
- 写明这是「**历史上出现过什么**」，不是「这次会怎样」；历史胜率不是未来概率。
- 口径限制必须带上：ETF 代理 ≠ 行业指数、样本 < 8 为低样本不可外推、快照超过 30 天为陈旧、非同类严格对照。
- **样本不可得时如实写「无历史统计可比」**，不得编造年份、案例、指数涨跌或「历史上通常上涨」这类口头结论。

### 5. 证伪条件与风险

给 2–3 条可证伪条件，提示「预期兑现」、新闻时点与口径不确定性、历史事件与本次不可简单类比。
明确区分三层：**新闻事实 / 程序计算 / 本次判断**。

## 硬性纪律（低幻觉要求）

- **不罗列指标**：程序分数、情感命中词、板块代码、统计条数、候选清单只作背景；只在与机制直接相关时引用 1–2 个，不得逐条复述、列成清单或写成 KPI。
- **不编历史**：所有历史数字只能来自 `event-study.json`；无样本就写不可得。
- **不改写事实**：金额、数量、百分比、日期、个股代码与名称逐字引用，不新增、不自行计算新数字。
- **不预判行情**：不预测涨跌必然性、不给点位 / 目标价 / 仓位，不出现买入、卖出、加仓、减仓、抄底、止盈、止损。
- **不冒充官方**：板块归类为关键词近似映射，须显式说明；`verified` 只表示日期是否确认，不代表真伪已裁定。
- **区分三层**：事实 / 程序计算 / 本次判断，凡判断必须标注并给证伪条件。
- **不确定就直说**：原文信息不足时写「暂难判断」并说明缺什么，不要脑补。
- **不写数据文件**：本技能只读与解释，不修改 `event-study.json`、日历、选股结果或任何评分。
- 引用纪律沿用 `grounded-citations`：每条判断都能回溯到原文或程序输出。

## 输出骨架（与后端 v3 一致）

非宏观事件（六段）：

```
## 一、这是什么事件
## 二、为什么重要：作用机制
## 三、对二级市场的影响判断
## 四、历史上同类情况下出现过什么
## 五、板块与标的观察（精简）
## 六、证伪条件与风险
```

命中官方 / 政府指数发布事件时追加三段（机构预期 / 跨资产 / 多数方向建议），
并逐字引用注入的免责声明；统计计数只引用一次，不得抄成清单。

固定段标题为骨架，段内用 `- ` 列表，关键结论加粗，禁止表格、图表、代码块、emoji。

## 与既有技能的关系

| 技能 | 关系 |
|---|---|
| `ashare-news-triage` | 前置层：先筛出「值不值得看」的新闻，本技能再解释「为什么、影响什么」 |
| `market-modules` | 数据层：提供 `event-study.json` 等快照；本技能只用其中的历史统计，不把行情数字当正文 |
| `grounded-citations` | 引用纪律来源：每条判断可回溯 |
| `research` / `feeds`（内置通用技能） | 只提供通用研究与读源能力，不含 A 股事件口径，不直接套用 |

## 维护

- 后端实现：`server/event-analogy.js`（确定性历史生成器）+ `server/news-flash.js`（v3 提示词）。
- `promptVersion`：`news-flash-v3-event` / `news-daily-v3-event`；宏观为 `news-flash-v3-macro` / `news-daily-v3-macro`。
- 事件统计刷新：后端 `POST /api/v2/agent/perception/refresh` 或 `event-study.refresh()`。
- 前端解读响应含 `historicalCard`：即使智能体不可用，历史统计卡片仍可展示。
